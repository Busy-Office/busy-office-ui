File upload

Attach a signed goods-receipt PDF, a vendor contract, a photo of a damaged shipment. A real <input type="file"> — the platform's own picker, keyboard access, and (Chrome/Firefox) native drag-drop onto the control come free; the framework styles it and adds one small opt-in behavior for a bigger drop target.

Basic

<input class="bo-file-input" type="file" aria-label="Attach a file">

::file-selector-button is the one part of a file input CSS can restyle — the "No file chosen" text stays native UA rendering, not something to fight.

Multiple files, restricted types

<input class="bo-file-input" type="file" multiple accept=".pdf,.jpg,.png" aria-label="Attach receipts">

multiple and accept are native attributes — no framework API for them, because there's nothing to add.

Dropzone — bigger drag target opt-in

<label class="bo-file-dropzone" data-file-dropzone>
  <input class="bo-file-input bo-visually-hidden" type="file" multiple aria-label="Attach vendor documents">
  <span>Drop files here, or click to browse</span>
  <span class="bo-file-dropzone__hint">PDF, JPG, or PNG — up to 10 MB each</span>
</label>

Try dragging a file over the box. Click anywhere in it to open the picker (a <label> wrapping an input forwards clicks — no JS needed for that part). initFileDropzone() only adds the highlight-while-dragging state and lets a drop anywhere in the box (not just the tiny native input) populate the file list.

With a selected-file list

  • goods-receipt-88213.pdf 412 KB
  • vendor-signature.jpg 1.1 MB

  </li>
  <li class="bo-file-list__item">
    <span class="bo-file-list__name">vendor-signature.jpg</span>
    <span class="bo-file-list__size">1.1 MB</span>
    <button class="bo-btn bo-btn--sm bo-btn--danger-ghost" type="button" aria-label="Remove vendor-signature.jpg">✕</button>
  </li>
</ul>

.bo-file-list styles rows YOUR code renders after reading input.files on change — same "framework does visuals, you do the data" split as everywhere else. No upload progress bar shipped here either: pair with the Progress component once a real upload is in flight — this framework doesn't do XHR for you.

Markup

<!-- The input is the real control — the label makes the whole box
     clickable and gives the input its accessible name. initFileDropzone()
     is optional: only adds drag-over highlighting + forwarding a drop
     anywhere in the box into the input (native drop-on-input already
     works without it, just only over the small native control). -->
<label class="bo-file-dropzone" data-file-dropzone>
  <input class="bo-file-input bo-visually-hidden" type="file" multiple
      aria-label="Attach vendor documents">
  <span>Drop files here, or click to browse</span>
</label>
<script type="module">
  import { initFileDropzone } from "@busy-office/ui/js";
  initFileDropzone();
</script>
<!-- File list + progress are YOUR code: read input.files on 'change',
     render .bo-file-list rows, upload however you upload. Put
     aria-live="polite" on the <ul> — a screen-reader user who just
     dropped or removed a file otherwise gets no confirmation it
     registered (same live-region need as the data-table selection
     count). -->

JS required Optional: initFileDropzone() — adds drag-over highlighting to a [data-file-dropzone] label and forwards a drop anywhere in it into the input's FileList (dispatching a real change event). The input works without it; drops just only land on the small native control.
  • Always give the input an accessible name — aria-label, or a visible <label> (which a dropzone already needs, to make the whole box clickable).
  • File type/size limits are native attributes (accept) or your own validation after reading input.files — nothing this component enforces.
  • No file list, upload, or progress bar shipped — read input.files on change and render .bo-file-list rows yourself; pair with Progress for an in-flight upload.
  • Put aria-live="polite" on the .bo-file-list — a screen-reader user who just dropped or removed a file gets no confirmation it registered otherwise (same live-region need as the data-table selection count).
