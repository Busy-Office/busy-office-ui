Filters

Filter bar + applied-filter chips. Each chip's remove button names its filter in the aria-label. Filtering itself is your code (form submit or HTMX).

Status: Pending CC-4021

Filtering something — bar + multi-select + matching rows

The full loop: the multi-select dropdown is where chip values come from, the active chip echoes the applied filter, the rows below match it. Also the base vs --active chip contrast — an inactive chip ("Overdue only") is an available filter, an active one is applied and removable.

Saved views opt-in

Views are just links (server-rendered, zero new CSS) — but which one is "active" and what the filter bar's fields show shouldn't be hand-set per page. initSavedViews() derives both from the URL: it reads location.search, fills matching .bo-filter-bar fields, and marks whichever [data-saved-views] link's own querystring matches the current one aria-current="page" — clearing it from the others. Try it: click a saved view below, watch the filter bar and the active chip update to match.

My pending Overdue All CC-4021

Markup

<!-- A real <form>, so type="reset" works and role="search" sits on it. -->
<form class="bo-filter-bar" role="search" aria-label="Invoice filters">
  <input class="bo-input" type="search" name="q" aria-label="Search invoices" />
  <select class="bo-select" name="status" aria-label="Status">…</select>
  <span class="bo-chip bo-chip--active">Status: Pending
    <button class="bo-chip__remove" type="button"
            aria-label="Remove filter Status: Pending">✕</button>
  </span>
  <button class="bo-btn bo-btn--ghost" type="reset">Clear all</button>
</form>
