Quantity

A count field, not a currency one — see Amount for money. A real type="number" input with increment/decrement buttons; min/max/step are native attributes, so validation, keyboard behavior, and the buttons' clamping all read from the same source of truth.

Basic

<div class="bo-quantity">
  <button class="bo-btn bo-btn--secondary bo-quantity__step" type="button" data-quantity-step="-1" aria-label="Decrease quantity">&minus;</button>
  <input class="bo-quantity__input" type="number" value="4" min="0" max="99" step="1" inputmode="numeric" aria-label="Quantity" />
  <button class="bo-btn bo-btn--secondary bo-quantity__step" type="button" data-quantity-step="1" aria-label="Increase quantity">+</button>
</div>

Requires initQuantity() — without it the buttons are inert, but the input itself still works (native number keyboard behavior, and it's a real form field either way).

With a unit

kg 
<div class="bo-quantity">
  <button class="bo-btn bo-btn--secondary bo-quantity__step" type="button" data-quantity-step="-1" aria-label="Decrease quantity">&minus;</button>
  <input class="bo-quantity__input" type="number" value="12" min="0" max="500" step="1" inputmode="numeric" aria-label="Quantity" />
  <button class="bo-btn bo-btn--secondary bo-quantity__step" type="button" data-quantity-step="1" aria-label="Increase quantity">+</button>
  <span class="bo-quantity__unit">kg</span>
</div>

__unit is optional, plain text — an ISO/standard unit (kg, m, L) or an app-defined custom UOM (box, pallet), same as Amount's __currency — no allowlist, just text.

Read-only display

Received 2.50 kg of 5.00 kg ordered.

<p>Received <span class="bo-quantity bo-quantity--display">
  <span class="bo-quantity__value">2.50</span>
  <span class="bo-quantity__unit">kg</span>
</span> of <span class="bo-quantity bo-quantity--display">
  <span class="bo-quantity__value">5.00</span>
  <span class="bo-quantity__unit">kg</span>
</span> ordered.</p>

--display is the read-only counterpart to the editable stepper — a span composition, no JS, sits inline in running text or a table cell. The same split as Amount (display) vs this component (edit): pick by whether the user changes the number here.

Interactive unit — precision follows it

<div class="bo-quantity">
  <button class="bo-btn bo-btn--secondary bo-quantity__step" type="button" data-quantity-step="-1" aria-label="Decrease quantity">&minus;</button>
  <input class="bo-quantity__input" type="number" value="2.50" min="0" step="0.01" inputmode="decimal" aria-label="Quantity" />
  <button class="bo-btn bo-btn--secondary bo-quantity__step" type="button" data-quantity-step="1" aria-label="Increase quantity">+</button>
  <select class="bo-select bo-quantity__unit-select" aria-label="Unit">
    <option>kg</option>
    <option>g</option>
    <option>each</option>
    <option>box</option>
  </select>
</div>

Swap the static __unit span for a real <select class="bo-select bo-quantity__unit-select">: changing unit re-derives the input's step/decimals from the built-in unit table (kg 2.50 → each 3 → g 3.00) and reformats the value — the same mechanics as the Money field's currency select. data-decimals on an option or the container overrides the table.

Fractional units — step IS the precision

kg 
<!-- fractional units (weight, volume, time) need a decimal step AND
     inputmode="decimal" — "numeric" implies an integer-only keypad on mobile -->
<div class="bo-quantity">
  <button class="bo-btn bo-btn--secondary bo-quantity__step" type="button" data-quantity-step="-1" aria-label="Decrease quantity">&minus;</button>
  <input class="bo-quantity__input" type="number" value="2.50" min="0" max="500" step="0.25" inputmode="decimal" aria-label="Quantity" />
  <button class="bo-btn bo-btn--secondary bo-quantity__step" type="button" data-quantity-step="1" aria-label="Increase quantity">+</button>
  <span class="bo-quantity__unit">kg</span>
</div>

Whole-count units (ea, box) use step="1" with inputmode="numeric"; fractional units (weight, volume, time) need a decimal step — 0.25, 0.01 — AND inputmode="decimal", since numeric implies an integer-only keypad on mobile. There is no --decimals modifier — a static field's precision is the step you write; a __unit-select field derives it from the built-in unit table below, with data-decimals overriding either way.

Unit decimals reference — the complete built-in table

Every unit the built-in table knows, case-insensitive. Anything not listed leaves the field's precision entirely alone — real master-data UOM codes (MT, ltr, cbm, bundle…) are almost never these exact strings, and an unknown unit must never rewrite your value (Slice 19 hardening: the earlier default-0 silently rounded fractional quantities). Unlike currencies there is no ISO-closed list of units, so this is a pragmatic common-ERP set — your data-decimals override extends it per field without waiting for the table.

<div class="bo-quantity">
  <button class="bo-btn bo-btn--secondary bo-quantity__step" type="button" data-quantity-step="-1" aria-label="Decrease quantity">&minus;</button>

Buttons disable at min/max — render the correct disabled server-side for the starting value; initQuantity() keeps it in sync reactively after that (clicking, typing, or the native spinner keys).

Composes with .bo-form-field like any other control — the same two-channel error state (border + message + aria-invalid or :user-invalid) applies for free, nothing quantity-specific needed.

Large-target (warehouse-floor) variant

<div data-density="spacious">
  <div class="bo-quantity">
    <button class="bo-btn bo-btn--secondary bo-quantity__step" type="button" data-quantity-step="-1" aria-label="Decrease quantity">&minus;</button>
    <input class="bo-quantity__input" type="number" value="4" min="0" max="99" step="1" inputmode="numeric" aria-label="Quantity" />
    <button class="bo-btn bo-btn--secondary bo-quantity__step" type="button" data-quantity-step="1" aria-label="Increase quantity">+</button>
  </div>
</div>

There's no separate "large" modifier — density IS the size variant. data-density="spacious" (44px controls) already meets the WCAG 2.5.8 minimum target size; scope it to a warehouse-floor screen the same way you'd scope compact to a dense table.

JS required None — CSS-only.
  • A count, not currency — see Amount for money values.
  • min/max/step live on the native <input type="number">; the step buttons read the same attributes, so there is only one source of truth for the valid range.
  • Button disabled state at a boundary is kept in sync reactively by initQuantity() — render the correct initial disabled server-side if the starting value is already at min/max.
  • Composes with .bo-form-field for validation — no quantity-specific error styling.
  • __unit accepts an ISO/standard unit or an app-defined custom UOM — no allowlist, same convention as Amount's __currency.
  • Decimal precision is expressed via the native step attribute, not a CSS modifier — fractional units need inputmode="decimal", not the default numeric.
  • With a __unit-select, precision follows the built-in unit table (see the reference above) — a deliberate, overridable exception to "your app owns the data", mirroring the Money field's currency table; data-decimals always wins.
  • --display is the read-only form — a span composition with __value + __unit, no JS; the same display-vs-edit split as Amount vs this component.
