Amount

A money or quantity value, laid out to scan down a column. This is CSS-first: your app formats the number (locale grouping, decimal precision, sign) and supplies the parts as markup — the component styles and aligns them, with tabular figures so every row lines up digit-for-digit. One component, driven by settings.

Money — symbol, grouping, minor units

$ 18,940.50 
<span class="bo-amount">
  <span class="bo-amount__currency">$</span>
  <span class="bo-amount__value">18,940<span class="bo-amount__fraction">.50</span></span>
</span>

__currency and __fraction are quieted so the whole-number part reads first.

Currency as an ISO code (either side)

1,234.00 EUR 
<span class="bo-amount">
  <span class="bo-amount__value">1,234.00</span>
  <span class="bo-amount__currency">EUR</span>
</span>

Source order decides prefix vs suffix — $ before, EUR/kr after. No modifier needed.

Custom / non-ISO currency

2,400PTS ₡18.50 
<!-- an app-defined currency (points, credits, store scrip) works exactly
     like ISO codes and symbols — __currency accepts any text -->
<span class="bo-amount"><span class="bo-amount__value">2,400</span><span class="bo-amount__currency">PTS</span></span>
<span class="bo-amount"><span class="bo-amount__currency">₡</span><span class="bo-amount__value">18.50</span></span> <!-- an internal "credit" symbol -->

Loyalty points, internal credits, any app-defined unit of value — __currency is plain text with no ISO allowlist. Same component, same alignment, no special-casing needed.

Precision — a setting, not a variant

¥56,000 $4,208.00 $0.0725
<!-- 0 decimals (whole units) -->
<span class="bo-amount"><span class="bo-amount__currency">¥</span><span class="bo-amount__value">56,000</span></span>

<!-- 2 decimals (money) -->
<span class="bo-amount"><span class="bo-amount__currency">$</span><span class="bo-amount__value">4,208.00</span></span>

<!-- 4 decimals (unit price / FX rate) -->
<span class="bo-amount"><span class="bo-amount__currency">$</span><span class="bo-amount__value">0.0725</span></span>

Whole units, money, or 4-dp unit prices — same component; the digits come from your formatter.

Decimal precision is app/domain data, not a CSS rule — there's no --decimals modifier, because "how many decimals does this currency get" varies by currency, not by design choice. A starting reference (override per field, never hardcode as a single app-wide constant):

CurrencyDefault decimalsExample
USD, SGD, EUR2$4,208.00
JPY, KRW0¥56,000
BHD, KWD, OMR3BHD 12.500
App-defined (points, credits, FX rates)your call2,400 PTS

ISO 4217 publishes the standard minor-unit table if you need it beyond this reference — most apps already get this from an Intl.NumberFormat call or a currency-master table, which is exactly where this belongs (not this CSS layer).

Negative & credit — two-channel

$(2,110.00) $−730.25 $+9,320.75
<!-- debit: parentheses OR a minus sign carry the meaning; red is the 2nd channel -->
<span class="bo-amount bo-amount--negative"><span class="bo-amount__currency">$</span><span class="bo-amount__value">(2,110.00)</span></span>
<span class="bo-amount bo-amount--negative"><span class="bo-amount__currency">$</span><span class="bo-amount__value">&minus;730.25</span></span>

<!-- credit: a + sign carries the meaning; green is the 2nd channel -->
<span class="bo-amount bo-amount--positive"><span class="bo-amount__currency">$</span><span class="bo-amount__value">+9,320.75</span></span>

The sign or parentheses live in the text, so colourblind and screen-reader users get the meaning without the colour. --negative/--positive only add the hue (both AA on surface and canvas, CI-gated).

Block — right-aligned totals on cards

PO-88213 total
$ 12,400.00 $ 1,240.00 tax

--block right-aligns a standalone amount — card totals, summary panels. Inside a table you don't need it: the cell's __col--numeric already aligns the column.

Unit of measure

4× EA $12.50/ kg $3.10/ pc
<!-- quantity × unit -->
<span class="bo-amount"><span class="bo-amount__value">4</span><span class="bo-amount__unit">&times; EA</span></span>

<!-- rate per unit -->
<span class="bo-amount"><span class="bo-amount__currency">$</span><span class="bo-amount__value">12.50</span><span class="bo-amount__unit">/ kg</span></span>

<!-- unit price beside a quantity -->
<span class="bo-amount bo-amount--muted"><span class="bo-amount__currency">$</span><span class="bo-amount__value">3.10</span><span class="bo-amount__unit">/ pc</span></span>

__unit carries × EA, / kg, pcs, hrs — a quantity’s unit or a rate’s denominator. This is a read-only display value; for an editable count with its own unit, see Quantity — same __unit convention, plus increment/decrement and native validation.

Editable money — a plain input, not .bo-amount

<!-- Amount (.bo-amount) is a DISPLAY value — a <span>, not a form control;
     there is no ".bo-amount--input" variant, on purpose (an <input> can't host
     __currency/__fraction as nested markup and stay a single accessible value).
     For an EDITABLE money field, compose .bo-form-field + .bo-input--numeric
     directly — the currency belongs in the label, not invented affix markup. -->
<div class="bo-form-field">
  <label class="bo-form-field__label" for="am-unit-price">Unit price (USD)</label>
  <input class="bo-input bo-input--numeric" type="number" id="am-unit-price" value="12.50" min="0" step="0.01" inputmode="decimal" />
</div>

.bo-amount is read-only display; it's a <span>, not a form control, and there's deliberately no input variant of it (the nested __currency/__fraction parts can't live inside a native <input> and still be one accessible value). For data entry, use a plain .bo-input--numeric field — put the currency in the label, the same way Quantity puts the unit in __unit text next to an editable control.

Markup

<span class="bo-amount">
  <span class="bo-amount__currency">$</span>              <!-- symbol or ISO code, either side -->
  <span class="bo-amount__value">18,940                 <!-- your app formats grouping + precision -->
    <span class="bo-amount__fraction">.50</span>         <!-- optional: quiet the minor units -->
  </span>
  <span class="bo-amount__unit">/ kg</span>              <!-- optional unit of measure -->
</span>

<!-- modifiers: --negative  --positive  --strong  --muted  --block -->

  • CSS-first: your app formats the number (locale, grouping, precision, sign); the component styles the parts and aligns them with tabular figures.
  • Negative/credit is two-channel — the sign or parentheses MUST be in the markup; --negative/--positive only add colour.
