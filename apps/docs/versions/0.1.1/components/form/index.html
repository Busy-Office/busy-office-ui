Forms

Form fields, sections, and layout for data entry. Validation state is CSS-driven via :has(), paired with the ARIA attributes that make it announced.

Fields (error styling is pure CSS via :has())

Registered vendor name (required — note the automatic asterisk)
Unknown cost center code

Required & disabled

Asterisk from the native required attribute.
--required class — for fields whose requiredness is enforced server-side only.
Disabled — system-assigned, never editable here.
Disabled select — fixed by company policy.

Density — the same row at compact vs spacious

One attribute on any wrapper — control heights, font sizes, and field gaps move together. Compact for back-office grids, spacious for touch/warehouse screens.

Seamless — inline edit that reads as text

Recorded value until hover/focus, then visibly a field: — the same input the data table uses for cell editing; it's a form input first, at home in prose and detail views too.

Markup — the canonical field recipe

<div class="bo-form-field">
  <label class="bo-form-field__label" for="cc">Cost center</label>
  <input class="bo-input bo-input--code" id="cc" required
         aria-invalid="true" aria-describedby="cc-error" value="CC-XXXX" />
  <span class="bo-form-field__message" id="cc-error" role="alert">
    Unknown cost center code
  </span>
</div>
<!-- CSS shows the error visuals; aria-describedby + role="alert" make it
     announced. Both halves are the contract, not just the :has() trick. -->
