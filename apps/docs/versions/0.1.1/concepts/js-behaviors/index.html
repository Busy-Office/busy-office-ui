JS behaviors

The framework is CSS-first, not CSS-only. 20 small behaviors (zero dependencies) cover what the platform can't do or what accessibility demands: each is a call-once init using document-level event delegation, so DOM swaps (HTMX, Alpine, anything) never require re-binding.

The inits generated

InitWhat it addsDOM hooks it reads
initDialogs() Dialog behavior via event delegation — no per-element binding, no DOM flags. data-dialog-trigger, data-dismissible, data-state
initDataTables() Optional table behavior (~1 kB): wires select-all, keeps an O(1) data-any-selected attribute on the container (so CSS needn't re-scan every row via :has() on large grids), and maintains a live "n… .bo-data-table-container, .bo-data-table__row-select, .bo-data-table__select-all, .bo-data-table__selection-count, data-any-selected

initRowEdit() Multi-row inline edit: tracks which rows have unsaved changes, shows a per-row Save/Cancel affordance, and dispatches a `bo:row-save` event for your code to persist (fetch, hx-patch, form submit —… .bo-badge, .bo-badge--warning, .bo-btn, .bo-btn--sm, .bo-data-table, .bo-data-table__row-edit-actions, .bo-input, .bo-input--seamless, data-row-edit, data-row-edit-cancel, data-row-edit-dirty, data-row-edit-save, data-row-id, data-row-state

Keyboard support generated

The four behaviors that own their own key handling — everything else is native (a plain <input>, a native <dialog>'s own focus trap) or has no keyboard surface (delegation-only behaviors like alerts). Extracted from source, so it can't drift from what's actually wired.

BehaviorKeyDoes
initCombobox() ArrowDown / ArrowUp open the list (filtering first if closed), then move the active option; clamps at the ends
Enter commit the active option (dispatches bo:combobox-select)
Escape close without changing the value (native popover light-dismiss)
initDataGrid() ArrowRight / ArrowLeft / ArrowDown / ArrowUp move the cell cursor; clamps at the grid edges
Home / End jump to the first/last cell in the row; with Ctrl/Cmd, the first/last cell in the grid
Enter focus the cell's one interactive widget, if it has one
Escape return focus from a widget to its parent cell
initDialogs() Escape close (native showModal(); skipped if data-dismissible="false")
Tab / Shift+Tab cycle focus inside the dialog, wrapping at the ends (focus trap)
initTabs() ArrowRight / ArrowLeft move to the next/previous tab, wrapping; activates immediately
Home / End jump to the first/last tab; activates immediately

The delegation model

Each init installs one document-level listener and resolves its target at event time; element-level listeners (a dialog's close handler) bind lazily on first use, tracked in a WeakSet — never serialized into the DOM. What you can rely on:

  • Triggers may render before their dialog exists.
  • Swapped-in content works without re-init.
  • Clone / morph swaps can't strand stale state.

Event wiring is swap-proof; derived state is re-computed. The one HTMX-aware line in core JS is the htmx:afterSwap event name a table container listens for:

// Bound table containers re-derive selection state automatically when an
// htmx:afterSwap bubbles through them. Any OTHER swap mechanism calls:
import { refreshDataTable } from "@busy-office/ui/js";
refreshDataTable(container);

// Only NEW containers swapped in later need re-binding:
document.body.addEventListener("htmx:afterSwap", (e) => initDataTables(e.target));

Intent events — the integration API generated

Behaviors never talk to your server; they dispatch an intent event and your app owns the data layer. These payloads are versioned API (see Versioning): a field changing shape or meaning is a Breaking change. This table is generated from the dispatch sites in source — it cannot drift.

EventDispatched onWhendetail
bo:cell-change the edited field (input/select/textarea; bubbles) a cell in a data-row-edit row changes — typing, a select pick, a checkbox toggle, or a behavior-driven reformat (money/unit precision). The realtime feed for subtotal math.
  • rowId {string|null} — the row's data-row-id
  • field {string|null} — the field's name, falling back to its aria-label
  • value {string|boolean} — the field's current value (checked for a checkbox/radio)
bo:combobox-select the combobox <input> (bubbles) an option is committed — click, or Enter on the active option
  • value {string} — the option's data-value, falling back to its text
  • text {string} — the option's visible text, now in the input
bo:row-cancel the cancelled <tr> (bubbles) Cancel is activated; native fields are already restored — listen to restore consumer-rendered cell content the framework doesn't own (e.g. tag-input chips)
  • row {HTMLTableRowElement} — the live row
  • rowId {string|null} — the row's data-row-id, or null if unset
bo:row-save the edited <tr> (bubbles) Save is activated on a dirty row (batch mode), or any change commits in data-row-edit="live" mode; after the event, current field values become the new baseline (Cancel restores to them)
  • row {HTMLTableRowElement} — the live row — read committed values from its inputs/selects by name
  • rowId {string|null} — the row's data-row-id, or null if unset
bo:scan the [data-scan-input] field (bubbles) the terminator key arrives (default Enter, data-scan-terminator to override); the field is cleared and refocused for the next scan
  • value {string} — the scanned string, exactly as entered
bo:table-export the [data-table-export] button (bubbles) the export button is clicked; the listener produces the file (server round-trip or client-side) — the framework only signals
  • format {string} — data-table-export-format, default "csv"
bo:table-load-more the [data-table-load-more] button (bubbles) the button is clicked, or scrolls into view (IntersectionObserver) — none
bo:tag-add the .bo-tag-input container (bubbles) Enter is pressed in the field with non-empty text; the field is cleared immediately
  • value {string} — the typed text — your code validates/dedupes and appends the actual .bo-tag-input__tag markup if accepted
bo:tag-remove the removed .bo-tag-input__tag (bubbles) its remove button is clicked, or Backspace is pressed in the field while empty (removes the last tag)
  • value {string} — the removed tag's text content

All bubble, so one document-level listener works per event type — the same delegation model the inits use:

document.addEventListener("bo:row-save", (e) => {
  const { row, rowId } = e.detail;          // typed shape: see the table above
  const values = Object.fromEntries(new FormData(row.closest("form")) );
  fetch(`/pos/${rowId}`, { method: "PATCH", body: JSON.stringify(values) });
});
