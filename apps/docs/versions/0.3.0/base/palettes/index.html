Palettes

Pick a brand in one look: every card is a live preview of a shipped preset (@busy-office/ui/css/brand-<name>), each gated through the full 32-pair AA contrast check in both themes — swatches, tokens, and hex generated from the CSS that actually ships. One import re-skins the whole framework; teal is the built-in default (no import). The theming guide has the recipe for defining your own.

Previews follow your theme toggle — light values in light, the palette's dark values in dark, exactly what an app importing it gets. Every accent in every card is an alias to a scale step; the build fails if one drifts to a raw hex.

Placement matters: import the preset after @busy-office/ui/css, outside any @layer — that ordering is what lets it win under the cascade contract. The installation page shows the full stylesheet order.

Your own palette

Same recipe, no framework changes: define the accent family (accent / strong / solid / subtle / text) plus focus-ring and bg-selected, in both light and dark blocks, unlayered, imported after the framework CSS. Copy any file above as a starting point, and add your file to the contrast gate's brand scan if you vendor the repo — the gate discovers src/css/brand/*.css automatically. Why palettes never touch status colors: success/warning/danger carry MEANING (approved, on hold, overdue) that must read identically across every brand — a re-skin that made "danger" olive would be a correctness bug, not a theme. Palettes re-skin identity (the accent family); semantics stay framework-owned.
