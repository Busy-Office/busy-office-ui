Pattern: object page — a long record, in sections

A long record, navigated in sections instead of scrolled as one feed. Who uses it: whoever owns one record end to end — a buyer opening a PO, an approver checking it before signing; many times a day, one object at a time. What "done" looks like: the reader can see the object's status without scrolling, reach any section in one click, and act on it from anywhere on the page. The long-record counterpart to record detail: same content, but too tall to take in at once, so it gains navigation of its own. Not for a record you can take in at one glance — the anchor rail and sticky action bar are overhead you only earn by being long. That one is record detail.

Scroll the sections: the anchor bar follows, marking the section you are in, and the header's facts collapse away so the record gets the screen back — the title and status never leave. Every part of this screen is a component that already ships — the only thing added is initAnchorNav(), and it writes no CSS.

Anatomy

  1. Object header — a plain widget carrying the title, a status badge, and the key facts as a kv list. Status is visible before any scrolling, which is the whole reason the header sticks.
  2. Anchor bar — pagination markup used as section navigation, because it already styles [aria-current="page"]. Kept to one line and allowed to scroll sideways; it carries tabindex="0" because a scrollable region must be reachable by keyboard. Reads like tabs, is NOT role="tab" — a real tabs widget hides every panel but the active one and moves between them with the arrow keys; this bar is plain links, every section stays in the DOM and on screen, and Tab visits each link like any other link. Activating one scrolls (Enter or a click), same as clicking any anchor — Chrome/Firefox/Safari all then resume keyboard Tab from the section just jumped to, not from the top of the document, even though it never becomes document.activeElement itself (verified live, 2026-08-22).
  3. One sticky wrapper — the header and the bar stick together, in a single sticky element. Two sticky children both at inset-block-start: 0 pin to the same offset and overlap.
  4. Sections — one widget per facet, each with the id the anchor bar targets.
  5. Action bar — .bo-form-actions, which is already sticky, already hidden in print, and already sets scroll-padding-block-end so focus never lands under it.

Follows the review-screen anatomy contract — this is the long-record shape; see that page for when a shorter record detail is enough.

Data contract

The screen is one GET of one object. Sections are regions of that response, not separate requests — anchor navigation is in-page, so there is no round trip when the reader moves between them.

  • GET /purchase-orders/:id → the whole object. Every section id in the anchor bar must exist in the response, or the link scrolls nowhere.
  • Actions post the whole object — POST /purchase-orders/:id/submit returns the re-rendered page, or a 4xx with the object plus errors. Swap the whole <main>: a partial swap would drop the sticky wrapper and the reader's scroll position with it.
  • A 409 (someone else edited it) returns the current object and a banner. Remember that htmx discards non-2xx by default — see editable grid.

States

StateWhat the screen shows
LoadingThe header skeletons first — status is the thing the reader came for. Sections fill in after.
Empty sectionThe section stays in the anchor bar and says why it is empty. Removing it would make the bar change shape between records.
Error in one sectionThat section shows the error; the rest of the object stays readable. A whole-page error for one failed facet loses the record.
Read-only / no permissionThe action bar is absent, not disabled — there is nothing to explain if the reader can never act.
Conflict (409)Banner above the sections, object re-rendered, anchor position preserved.
PrintSticky chrome and the action bar drop out; sections print in order as one continuous document.

Markup

<div class="op-sticky">                        <!-- ONE sticky wrapper -->
  <header class="bo-widget">…object header: title, status, key facts…</header>
  <nav class="bo-pagination" data-anchor-nav tabindex="0" aria-label="Sections">
    <a class="bo-pagination__btn" href="#general" aria-current="page">General information</a>
    <a class="bo-pagination__btn" href="#items">Line items</a>
  </nav>
</div>

<section class="bo-widget" id="general">…</section>
<section class="bo-widget" id="items">…</section>

<div class="bo-form-actions">                     <!-- already sticky + print-hidden -->
  <button class="bo-btn bo-btn--secondary" type="button">Discard</button>
  <button class="bo-btn" type="submit">Submit for approval</button>
</div>
