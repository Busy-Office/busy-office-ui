Pattern: schedule calendar

A planner or supervisor scans a month for what is booked — deliveries, maintenance windows, shift cover — several times a day during a busy week, and once a day otherwise. "Done" is picking a day and seeing exactly what is on it without losing the month underneath, the same swap discipline master-detail uses for a list and a record. Not for authoring a schedule — creating, moving or cancelling entries is the admin module's job, not this screen's — and not for one entry's own detail or history, which belongs to record detail, not a month grid. This page only answers "what is on this day".

The month stays put while the day-detail list changes — the calendar is never re-rendered on a click, so the reader's place in the month survives. Only days carrying at least one entry are real links; an empty workday is a plain cell, the same "not everything is clickable" discipline the calendar component's own picker uses.

Which day is open is carried the same way master-detail carries row selection — data-day="selected" on the cell, which is the calendar component's own state, reused rather than invented. There is no second "which day is open" mechanism to keep in sync with it.

Anatomy

  1. Month grid — calendar; a day with entries is a real link, a day with none is a plain cell.
  2. Which days carry work — the calendar's own data-day marks (closed, holiday, today) plus whether the cell is a link at all; no new attribute for "has entries", the link/no-link distinction already carries it.
  3. Open-day indicator — data-day="selected" on the chosen cell, the same value the calendar's picker already ships.
  4. Day-detail panel — a card beside the month, holding a compact data table of that day's entries with a status badge per row.

Data contract

RequestReturns / on failure
GET /schedule?month=2026-08the month grid, with each day's data-day mark and whether it is a link baked in server-side; the detail panel renders empty until a day is chosen
GET /schedule/day/:datethe day-detail fragment only, swapped into #schedule-detail. Never re-render the month — that is what loses the reader's place in it
404 / day now emptyan entry was cancelled after the month rendered — replace the panel with an empty state naming the day, and stop treating that cell as a link on the next month fetch
GET /schedule/day/:date on a closed or holiday datenever happens from a click (those cells are plain spans, not links); a bookmarked URL still gets a real answer: an empty state saying the works calendar has no entries possible that day

No AI-manages/human-monitors split here, stated rather than left silent: this screen is a planner reading and booking dates, not oversight of an automated process — the closed/holiday marks are static business rules, not something an agent manages behind the scenes. There is no monitoring signal to name.

States

StateWhat ships
Nothing selectedthe panel holds a one-line prompt ("Pick a day to see what's on it"), not a blank box
Loading the dayaria-busy on the panel only; the month stays interactive so the reader can pick a different day mid-load
Empty daya day that IS a link (server said it has entries) but returns none by the time it's opened — say so, do not show an empty table with headers and nothing under them
Non-working day opened via a bookmarkthe DIFFERENT empty — explain it is a closed/holiday date, not "nothing scheduled yet"
Conflict on one entryflagged in the row with a badge (see the demo above), not surfaced as a page-level error — the other entries that day are still fine
No permission to open a day's detailthe day stays a plain cell rather than a disabled-looking link — a control a reader can see but never use is worse than one that is simply absent
Narrow screenpanel and grid stack in source order — the split's own auto-fit grid (see .sched-split below) collapses to one column below ~36rem; the calendar component itself carries no container breakpoint, nothing new to build here
No JSfully functional — this page has no JS dependency; each day is a real <a href="#schedule-detail"> fragment link (native anchor navigation, no script), and the page imports no @busy-office/ui/js behavior
