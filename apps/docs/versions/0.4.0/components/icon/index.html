Icon

CSS-rendered icons: an inline-SVG mask-image painted by currentColor — real, themable glyphs with zero JS, zero font files, no network requests. Sized 1em, so they track the surrounding font size (and density) automatically. The set is deliberately small: twelve ERP glyphs prove the mechanism; adding your own is one line of CSS — or paste inline SVG with fill="currentColor", which is an equally first-class answer. Not as the only label for a meaning the reader has to learn — an icon-only control works when the glyph is already a convention (close, search, settings) and space is genuinely tight, and then it still needs an aria-label, since these glyphs are aria-hidden decoration. It fails the moment the meaning is domain-specific: nobody recognises a mark for "post goods issue", so that button needs its words. And where no glyph in any set reads as the thing — "accounts payable" has none — use letters: an initials badge is honest where an approximate icon is confidently wrong.

The set

--doc --invoice --cart --check-circle --truck --box --chart --grid

Convenience presets for ERP concepts common enough to be worth shipping a name for — each is just a value of --bo-icon-src, same as your own would be (next section).

Deprecated 4

--settings --barcode --building --user

No pattern screen in these docs renders any of these four — only this showcase did. Kept shipping (removing published classes is a next-major change, not a tidy-up) but no longer recommended: point --bo-icon-src at your own SVG instead (next section).

Themable — it's just currentColor

Set color (or inherit it) and the glyph follows — semantic tokens, dark mode, and brand presets all work with no icon-specific wiring. Under forced-colors the icons repaint in the system text color instead of vanishing (mask icons need an explicit opt-out; shipped).

Sizes — font-size IS the size

No size modifiers: 1em means an icon in a compact table row is smaller than one in a spacious header for free.

In context — sidebar links and icon buttons

  • Invoices
  • Approvals
  • Shipments

Composes with the existing .bo-sidebar-nav__icon slot and .bo-btn--icon — decorative icons carry aria-hidden; an icon-only button labels itself with aria-label, never the icon. Both buttons here pass the opener's test deliberately: a cog for settings and a bar chart for reports are conventions a reader already holds. The same treatment on a domain action — "post goods issue" — would not be, and that button gets its words.

Any icon you like — one custom property

The twelve glyphs above are not a privileged list: each one is just a value of --bo-icon-src. Point that property at any SVG and the element gets the framework's sizing, currentColor painting, density tracking and forced-colors handling with no new class from us.

Add line
View code 
<span class="bo-icon" aria-hidden="true"
  style="--bo-icon-src: url('data:image/svg+xml,<svg xmlns=&quot;http://www.w3.org/2000/svg&quot; viewBox=&quot;0 0 24 24&quot; fill=&quot;none&quot; stroke=&quot;%23000&quot; stroke-width=&quot;2&quot; stroke-linecap=&quot;round&quot;><path d=&quot;M12 5v14M5 12h14&quot;/></svg>')"></span>
<span>Add line</span>

That works with Lucide, Heroicons or your own brand mark — copy the SVG, percent-encode # as %23, and set the property. Icons drawn with stroke="currentColor" need no edit at all, because the mask ignores the SVG's own colours and paints with yours.

Why there is no 200-icon catalogue here, since that is the obvious thing to ask for: these twelve are 5.8% of the whole framework by size, because every glyph is an inlined SVG. Two hundred of them would add roughly 75 kB — more than everything else we ship — to compete with icon sets that are better maintained and free. One property is the smaller answer and the more general one.

Your own artwork — which mechanism, and when none

Four questions come up as "can we have SVG for this?". Three already have an answer that ships, and the fourth is a no.

You wantUseWhy
A one-colour glyph --bo-icon-src on .bo-icon It is a mask, so it takes your text colour and follows the theme, density and forced-colours handling automatically
A multi-colour mark — a logo, a vendor identicon a plain <img>, inside the avatar if it is a person or an org A mask cannot do this. It discards the artwork's own colours by design — that is what makes it themable. Multi-colour means an image
A per-tenant app tile the app launcher's inline svg slot Already the extension point: an inline <svg> inherits currentColor exactly like the shipped glyphs
An initials avatar no SVG at all — .bo-avatar with two letters in it Text scales, translates, is selectable and needs no asset pipeline. Generating an SVG for it would be strictly worse

What this framework will not ship: an illustration set. Empty states and error screens are the places an ERP feels most broken, and the fix is almost always a clear sentence and the action that resolves it — not a drawing. A picture that has to be redrawn for every tenant's brand, translated for nothing, and downloaded on a warehouse tablet is cost without an answer. If you want one, it is an <img>, and it is alt="".

Markup

<!-- Decorative (label carries the meaning): -->
<a class="bo-sidebar-nav__link" href="/invoices">
  <span class="bo-icon bo-icon--invoice" aria-hidden="true"></span>
  <span class="bo-sidebar-nav__label">Invoices</span>
</a>

<!-- Icon-only control labels ITSELF, never the icon: -->
<button class="bo-btn bo-btn--ghost bo-btn--icon" aria-label="Settings">
  <span class="bo-icon bo-icon--settings" aria-hidden="true"></span>
</button>

<!-- Add your own glyph in one line (any single-color SVG works): -->
<style>
  .my-icon--rocket { mask-image: url("data:image/svg+xml,<svg …></svg>"); }
</style>

Component tokens --bo-icon-src
JS required None — CSS-only.
  • Painted by currentColor via mask-image — themes, dark mode, and brand presets apply with zero icon-specific wiring; no new contrast pairs needed (an icon inherits the already-gated color of its text context).
  • Decorative icons (next to a visible label) are aria-hidden="true"; icon-only controls label THEMSELVES (aria-label on the button/link).
