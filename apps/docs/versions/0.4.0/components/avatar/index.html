Avatar

Who a thing belongs to, at a glance — initials or a photo in a disc: assignee columns, approval chains, bylines. Always decoration (aria-hidden) with the name as real text nearby; it scales with the text it sits beside. Not as the only way to name someone — a disc of initials in an Assignee column, with no name beside it, asks every reader to decode "JK" and gives a screen-reader user nothing at all, since the avatar is aria-hidden by contract. Pair it with the name as real text — byline does exactly that — or, in a dense table, drop the disc and keep the name: the column is scanned and sorted on the text, never on the picture.

Initials

RV JK
View code 
<span class="bo-avatar" aria-hidden="true">RV</span>
<span class="bo-avatar" aria-hidden="true">JK</span>

A span with two letters. The disc is em-sized, so it follows the font size of its context — put it in a compact table and it shrinks with the rows, no modifier needed.

Photo

View code 
<span class="bo-avatar" aria-hidden="true">
  <img src="data:image/svg+xml,%3Csvg xmlns='http://www.w3.org/2000/svg' viewBox='0 0 32 32'%3E%3Crect width='32' height='32' fill='%230f766e'/%3E%3Ccircle cx='16' cy='12' r='6' fill='%23ccfbf1'/%3E%3Cellipse cx='16' cy='27' rx='10' ry='8' fill='%23ccfbf1'/%3E%3C/svg%3E" alt="">
</span>

An img fills the disc (object-fit: cover). Keep alt="" — the identity belongs in the adjacent text, not in the picture.

Approval-chain stack

RV JK MO
View code 
<!-- approval chain: DOM order = approval order -->
<div class="bo-avatar-stack" role="img" aria-label="Approvers: R. Vasquez, J. Kim, then M. Osei">
  <span class="bo-avatar" aria-hidden="true">RV</span>
  <span class="bo-avatar" aria-hidden="true">JK</span>
  <span class="bo-avatar" aria-hidden="true">MO</span>
</div>

The "who's next" strip: discs overlap with a surface-colored ring, DOM order is approval order. The stack itself carries the accessible name (role="img" + aria-label listing the chain) — one announcement, not three fragments.

<table class="bo-data-table" data-density="compact">
  <thead><tr><th scope="col">Invoice</th><th scope="col">Assignee</th></tr></thead>
  <tbody>
    <tr><td>INV-10234</td><td><span class="bo-byline"><span class="bo-avatar bo-byline__avatar" aria-hidden="true">RV</span>R. Vasquez</span></td></tr>
    <tr><td>INV-10235</td><td><span class="bo-byline"><span class="bo-avatar bo-byline__avatar" aria-hidden="true">JK</span>J. Kim</span></td></tr>
  </tbody>
</table>

Composed with Byline: the avatar takes both classes — .bo-avatar paints the disc, .bo-byline__avatar tells the byline to lay out as a flex row.

Markup

<!-- Decoration, not a caption: aria-hidden always, the NAME is real
     text nearby (a byline, a cell, a stack's aria-label). em-sized —
     it scales with the surrounding text, no size modifiers. -->
<span class="bo-avatar" aria-hidden="true">RV</span>

<!-- photo variant: img fills the disc; alt stays empty -->
<span class="bo-avatar" aria-hidden="true"><img src="…" alt=""></span>

<!-- inside a byline, compose both classes (byline's :has() keys on the
     second one to switch to a flex row) -->
<span class="bo-byline">
  <span class="bo-avatar bo-byline__avatar" aria-hidden="true">RV</span>
  R. Vasquez · <time datetime="2026-08-16">today</time>
</span>

API generated from CSS

Blocks bo-avatarbo-avatar-stack
JS required None — CSS-only.
  • Always aria-hidden="true" — the avatar is decoration; the name is real text beside it (byline, cell) or on the stack (role="img" + aria-label).
  • No size modifiers by design: the disc is em-sized and inherits scale from its context (density, byline --compact, headings).
  • Stack order is DOM order — put the current/next approver first and say so in the aria-label.
  • Forced colors: the disc keeps a real border, so stacked avatars stay separable when backgrounds flatten.
  • Promoted from Byline (owner call 2026-08-16): markup that carried only .bo-byline__avatar must add .bo-avatar — listed as Breaking in the CHANGELOG.
