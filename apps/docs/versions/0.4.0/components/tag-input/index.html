Tag input

Multiple discrete values on one field — cost centers tagged on a record, several recipients on an approval-routing rule. No native element covers this (unlike file/date/segmented), so it's real JS — the same class as Combobox. The framework owns removal (it's deleting its own rendered chip); addition is yours: Enter dispatches an event with the typed text, you decide whether to accept it. Not for a small fixed set — three or four known options read better as checkboxes in a form field, and if only ONE value is allowed it is a Combobox.

Basic — cost centers

CC-4021 CC-2205

Type a value and press Enter to add it; click a tag's × (or press Backspace in the empty field) to remove the last one. Try it — this demo rejects exact duplicates, same as a real consumer would.

Approval-routing recipients

j.kim@busy-office.example

Empty

The container works with zero tags — no special empty-state markup needed.

Markup

<!-- The framework owns REMOVAL (it's the framework's own rendered
     chip) but not ADDITION: Enter dispatches bo:tag-add with the typed
     text and clears the field — YOUR code validates/dedupes and appends
     the actual .bo-tag-input__tag markup if accepted. -->
<div class="bo-tag-input" role="group" aria-label="Cost centers">
  <span class="bo-tag-input__tag">CC-4021
    <button class="bo-tag-input__remove" type="button" aria-label="Remove CC-4021">×</button>
  </span>
  <input class="bo-tag-input__field" type="text" aria-label="Add a cost center" placeholder="Add a cost center…">
</div>
<script type="module">
  import { initTagInput } from "@busy-office/ui/js";
  initTagInput();

  document.addEventListener("bo:tag-add", (e) => {
    const group = e.target.closest(".bo-tag-input");
    // Your validation/dedup goes here — this demo just rejects blanks
    // (already guarded by the behavior) and exact duplicates.
    const existing = [...group.querySelectorAll(".bo-tag-input__tag")]
      .map((t) => t.firstChild.textContent.trim());
    if (existing.includes(e.detail.value)) return;

    const tag = document.createElement("span");
    tag.className = "bo-tag-input__tag";
    tag.append(e.detail.value + " ");
    const remove = document.createElement("button");
    remove.className = "bo-tag-input__remove";
    remove.type = "button";
    remove.setAttribute("aria-label", `Remove ${e.detail.value}`);
    remove.textContent = "×";
    tag.append(remove);
    group.querySelector(".bo-tag-input__field").before(tag);
  });
</script>

JS required Required: initTagInput() — without it, Enter/Backspace do nothing and remove buttons don't remove their tag.
  • The framework owns REMOVAL only — a remove-button click or Backspace-on-empty deletes the framework's own rendered `.bo-tag-input__tag` and dispatches `bo:tag-remove`. Addition is yours: Enter dispatches `bo:tag-add` with the typed text and clears the field; validate/dedupe and append the tag markup yourself.
  • Keyboard access to remove buttons is plain Tab order — they're real button elements, no reimplemented roving-tabindex needed.
  • Wrap the group in `role="group"` with an `aria-label` naming what the tags represent (cost centers, recipients) — a native group has no accessible name of its own.
  • Works with zero tags — no special empty-state markup.
