### 3a. The critic's two blocking gaps

**Gap 1: does anything in the full chain catch 377-F1? No.** Three
injections were each appended to `button.css` in their own worktree of
`3f906b97`, and each was asserted by a fixed-string count (0 before, 1 after):
- A: `.bo-btn:focus-visible { outline: none !important; }`
- B: `.bo-btn:focus-visible { outline-style: none; }`
- C: `.bo-btn { --bo-focus-ring-width: 0; }`

Exit codes (npm ci / core build / docs build / check-claims / vitest /
forced-colors):
- A: 0 / 0 / 0 / **1** / 0 / 0
- B: 0 / 0 / 0 / 0 / 0 / 0
- C: 0 / 0 / 0 / 0 / 0 / 0

**Both builds are green on all three,** and the ACR ships 2.4.7's "is never
suppressed: 0 `outline: none`" in all three. A real Tab press shows the ring
gone on every `.bo-btn` (A computes `none 3px`, B `none 2px`, C `solid 0px`),
while the skip link on the same page keeps `solid 2px`.

**The one red is for the wrong reason.** check-claims' quantity case
(`check-claims.mjs` near 4539) adds outline offset and width and never reads
`outline-style`. `outline: none` resets the width to `medium`, which Chrome
computes as 3px, so the "ring" reads 1px wider and overlaps its neighbour. The
case reports an overlapping ring where there is no ring at all. B and C pass
it. 377-F1 stands as written.

**Gap 2: the checkbox in the grid, which is 377-F5. It is a live defect, now
P0 406.6.** On `/components/table-toolbar/`, real keys (Tab, Tab, ArrowDown,
Enter, Space) put focus on a checked checkbox, which matches `:focus-visible`,
in all 14 configurations. `.bo-data-table[role="grid"] :focus-visible
{ outline-offset: -2px }` paints the 2px ring inside the 16px box, on the
checkbox's own accent fill.
- **Under 3:1 in all 28 readings** (14 configurations × 2 checkboxes).
- **Exactly 1.00:1 in all six brand-dark presets.** Each brand's dark block
  sets `--bo-color-focus-ring` to the same step as `--bo-color-accent`
  (indigo-400 and indigo-400, blue-300 and blue-300, green-400 and green-400,
  read from source). A focused, checked checkbox is pixel-identical to an
  unfocused one outside 76 of 4,096 device pixels.
- **The rest:** base-dark 2.01; the light presets 1.25-1.55.
- **The agent's red-proofs:** a red ring colour shows the sampled points are
  ring pixels, and a +2px offset moves the ring off the fill.
- **Screenshot:** `grill-406/gaps/shots/indigo-dark-grid-wide-focused.png`,
  viewed here.
- **Why no gate saw it:** `RING_GROUNDS` lists canvas, surface,
  surface-raised, muted and selected, and never `--bo-color-accent`, the fill
  of a checked native checkbox.
- **Not covered:** unchecked and indeterminate states, hover, forced colours,
  Firefox and Safari, and inset rings on other grid controls.
