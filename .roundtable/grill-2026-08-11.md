# Design grill — busy-office-ui slice 1 · 2026-08-11

Panel per `.roundtable/PANEL.md`: Consumer (Devi, docs-only), Platform (Kofi, shipped
dist), Auditor (Ines, WCAG 2.2 AA), Skeptic (Rex, red team). All findings were produced
against the built artefacts: rendered docs at localhost:4173 and `packages/core/dist/`.
Full seat transcripts are summarised; the chair synthesises and does not vote.

## Verdicts by seat

| Seat | Verdict |
|---|---|
| Consumer | **Not today** — trial-adopt 2–3 screens; flips to yes after reference docs + slice 2 |
| Platform | **Conditional GO** — cascade architecture sound; K1/K2 are merge-blockers |

## Convergent findings (independently found by ≥2 seats — treat as CONFIRMED)

1. **Dark theme status badges fail contrast** (Ines A2 computed 2.1–2.9:1; Kofi K7).
   `[data-theme="dark"]` remaps `*-subtle` backgrounds but never the `*-strong`
   foregrounds badges use. Dark mode is unusable for the core ERP status signal.
2. **"Select all" is a dead, labeled control in the flagship pattern** (Ines A6, Rex R3,
   Devi #8 adjacent). No JS ships for tables; the checkbox triggers nothing — an
   accessibility own-goal, and the sort button is equally decorative and undocumented.
3. **Frozen first column desyncs from row states** (Kofi K8, Rex R4). Sticky cells paint
   opaque `bg-surface` over the `tr`-level hover/selected/striped/error backgrounds —
   the selected row looks unselected in exactly the column holding the checkbox.
   Bonus: sticky header z-1100 paints over dropdowns at z-1000.
4. **Two DESIGN.md absolutes are falsified by one line each** (Kofi K5/K6, Rex R7/R8):
   `.htmx-settling` hardcodes a 600ms flash that bypasses the reduced-motion token
   strategy, and the select chevron uses physical `background-position: right` plus a
   light-mode gray frozen in a data URI (breaks RTL and dark theme).
5. **Fail-closed `:has()` with no stated browser floor** (Kofi K2, Rex R6). The shipped
   error selector uses `:user-invalid` inside `:has()` (floor ≈ Chrome 119 / Safari
   17.4) — below it, error messages are *permanently hidden* and DESIGN.md documents a
   different, looser selector than dist ships. No browserslist, no support table.
6. **The à-la-carte story is dishonest in both directions** (Kofi K1/K3, Rex R10).
   Component dist files embed 7.3 kB of tokens each but omit the reset rules they
   depend on (`border-collapse`, button normalization) — the homepage's own recommended
   import combination renders broken tables; and past ~3 files, granular imports cost
   more than the full bundle (5 components ≈ 49 kB vs 29 kB for everything).

## Single-seat findings that stand on their own

- **R1 (Skeptic, BLOCKER): the dialog bind-flag design breaks under the advertised
  HTMX lifecycle.** Swapped-in dialog without its trigger → never bound, stale closure
  throws on a detached node; trigger-before-dialog → flag set before the null-check,
  permanently dead; clone-swaps copy the flag without listeners. `initDialogs(root)`
  cannot repair any of these. The only JS shipped fails exactly where the HTMX claim
  needs it. This is a binding-model rewrite, not a patch.
- **R2 (Skeptic, HIGH): the automatic required-asterisk selector
  (`:has(+ * [required])`) cannot match the framework's own canonical label+input
  markup** — it requires an undocumented wrapper. No demo uses `required`, which is why
  it went unnoticed.
- **A1 (Auditor, BLOCKER): collapsed sidebar links have empty accessible names** — the
  container query `display:none`s the label, the icon is `aria-hidden`, nothing is
  left. The `.eof-visually-hidden` class ships but the component never uses it.
- **A3/A5 (Auditor, HIGH): the zero-JS `:has()` signature patterns have zero
  programmatic semantics.** Error messages are never `aria-describedby`-associated and
  appear silently; the bulk toolbar appears upstream of focus with no live region. A
  screen-reader user gets "invalid entry" with no reason and never learns Approve/
  Reject exist.
- **A7 (Auditor, HIGH): dialog has no accessible name** — one `aria-labelledby` fixes it.
- **Devi #1–#5 (Consumer, BLOCKER/HIGH): the contract is only learnable by
  view-source.** No markup reference or class index anywhere; no documented JS import
  path (`initDialogs` named, specifier never shown, and the docs page inlines its own
  copy instead of importing the package); HTMX integration documented only in
  DESIGN.md, which npm consumers never see; badge and all layout primitives
  undocumented.
- **R5 (Skeptic, MEDIUM): container-query compaction silently beats an explicit
  `data-density="spacious"`** — and only overrides 3 of 6 density aliases, producing a
  mixed state; the toolbar doesn't compact with the cells.
- **K4 (Platform, MEDIUM, NEEDS-RUNTIME): container-level `:has(:checked)` re-evaluates
  the full subtree; un-checking the last row on a 5,000-row table is O(rows).**
- **R9/A17: focus trap can select hidden elements as first/last and let Tab escape.**
- **R11: `--eof-z-dialog/-backdrop` are fiction** — native `<dialog>` top layer ignores
  z-index; a consumer's z-1600 toast cannot float above an open dialog.

## What survived falsification (record, so it isn't re-litigated)

Layer hygiene is genuinely excellent: identical `@layer` order statement in every dist
file, idempotent under any import combination, verified intact through the Astro
bundler; the unlayered-consumer-wins escape hatch works end-to-end. Exports map fully
honest. HTMX decoupling holds (zero htmx refs in core). Density token remap, print
styles, sticky thead, tabular-nums, focus-visible ring, scrollbar-gutter, reduced-motion
for token-driven animations, light-mode text palette (AA-clean, ratios 4.8–7.6) all
verified true. ESC→state sync and double-bind protection correct *when binding happens*.

## Tensions (recorded, not smoothed)

- **The signature feature is the failure mechanism.** Ines: zero-JS `:has()` patterns
  "systematically trade programmatic semantics for CSS elegance." Devi: those same
  patterns are why she'd bet on the framework. Chair's read: the visuals can stay
  CSS-only, but every `:has()` pattern needs a documented, mandatory semantic
  counterpart (aria-describedby, live region) — and two of them (select-all,
  selected-count) simply need the small JS the framework was avoiding on principle.
  Purity lost; claim "zero JS" must be reworded to "zero JS for visuals."
- **Kofi's conditional GO vs Rex's NO-GO** is not actually a disagreement about facts —
  both blockers (K1/K2, R1/R2) are in the other's fast-follow list. The union is the
  gate, not the intersection.
- **Docs-vs-artifact drift**: three "throughout/all" absolutes in DESIGN.md each
  falsified by one line. Either the doc is the contract (then dist is wrong) or dist is
  the contract (then the doc must stop over-claiming). The panel is unanimous that the
  drift itself is the hazard, wherever the fix lands.

## Gate to slice-1 sign-off (union of seat blockers)

1. R1 — rewrite dialog binding (event delegation or WeakSet, bind dialogs independently
   of triggers, no serialized DOM flags).
2. A1 — visually-hidden labels in collapsed sidebar.
3. A2/K7 — dark-mode `*-strong` token remaps (or gate dark theme out of slice 1).
4. K1 — make à-la-carte files carry the element defaults they need, or pull the
   granular exports until honest; fix the homepage recipe.
5. K2/R6 — state the browser floor; add non-`:has()` fallback for the error message;
   align DESIGN.md selector with dist.
6. A3/A5/A6+R3 — canonical form recipe gains `aria-describedby`+`role=alert`; bulk
   pattern gains a live region; select-all becomes functional (small table behavior) or
   is removed from every demo.
7. A7 — `aria-labelledby` on the dialog recipe.
8. R2 — fix or delete the automatic required-asterisk selector.
9. DESIGN.md rewording: "all animations" (htmx flash), "RTL-safe throughout" (chevron),
   "zero JS", "tree-shakable" — make each true or scope it honestly.

## [HUMAN CALL]s

- **Browser floor.** Recommended default: declare Baseline-2024 floor (Chrome 119 /
  Safari 17.4 / FF 121), add the 3-line non-`:has()` error fallback, add browserslist.
  Cost: trivial now, permanent support-matrix commitment.
- **Table JS.** Recommended default: ship a ~50-line optional `initDataTables()`
  (select-all, selected-count live region, `data-any-selected` for O(1) toolbar
  reveal — also retires K4). Cost: "zero JS for tables" purity claim dies.
- **À-la-carte exports.** Recommended default: keep, but restructure — stop embedding
  tokens (document "import tokens+reset first"), embed only needed element defaults,
  minify per-component files. Cost: build-script rework, breaking change to import
  semantics before anyone depends on them (now is the cheapest moment).
- **Dark theme scope.** Recommended default: fix the strong-token remaps now (small),
  still market dark as slice-2. Cost: minutes.
