## Defect A — Slice 320's blast radius is 17 sweeps, not five, and they are not consecutive

Published: the wrong noun *"has been quoted as a declaration count in **five
consecutive sweep write-ups (214, 284, 290, 301, 314)**"*.

Re-derived whitespace-normalised, each hit attributed to its containing
`## Slice` heading:

```
python3 - <<'PY'
import re
pat = re.compile(r'1,?433[^.\n]{0,40}live inline\s+decl', re.I|re.S)
for f in ['ROADMAP.md','ROADMAP-archive.md']:
    txt=open(f).read()
    heads=[(m.start(), m.group(1)) for m in re.finditer(r'^## Slice (\d+)', txt, re.M)]
    print(f, sorted({[n for s,n in heads if s<=m.start()][-1]
                     for m in pat.finditer(txt)}, key=int))
PY
```

| reading | slices |

| of which **Standardize sweeps**, from their own headings | **17 of 17** — nothing else is in the set |
| quoting the noun at **any** value (the 1,428 era too) | **23** — the above plus 161, 166, 169, 187, 191, 194, 197, 202, 206 |

Ten of the 17 sit *between* 214 and 314, so **"consecutive" is false as well as

ever quoted this number correctly**, for the whole life of the instrument.

### The reusable half: this grill's own first scan made the same mistake

A line-based scan returned **16 of the 17** and missed exactly **301**, whose
`live inline` and `declarations` straddle a newline. That is not a coincidence
with 320's undercount — it is the same mechanism. This repo's prose is
hand-wrapped at ~78 columns, so a phrase-count taken per line silently drops
every wrapped instance.

It was caught only because 320 *named* 301 and the scan did not find it: a
hand-written list disagreeing with an instrument, which `LOOPS.md` already
records as the way this class of bug gets found. Filed as **322.3**, with the
base rate to be measured before anything is built.

## Defect B — Slice 304's base rate is not reproducible, and a re-derivation disagrees

Published in `304.1`: *"Of the **11** published full-ratio figures
(`N / M = P%`) across `ROADMAP.md`, `ROADMAP-archive.md` and
`.roundtable/RESUME.md`, **7 reproduce at the PARENT** of the commit carrying
them and **4 at the commit itself**, and only **3 of the 11** name a revision."*

This is the number that **refused the refusal** — the measurement that
authorised building the fix rather than declining it as ceremony.

**No command was recorded beside it.** That is precisely the omission 304
diagnoses in Slice 301 two paragraphs earlier in the same item, quoting
CLAUDE.md: *"had the command sat beside the claim, its `--rev` flag would have
made the error visible while writing."* So it can only be re-derived:

```
for f in ROADMAP.md ROADMAP-archive.md .roundtable/RESUME.md; do
  git show 8beee329:$f |
  grep -noE '[0-9][0-9,]*\s*/\s*[0-9][0-9,]*\s*=\s*[0-9]+(\.[0-9]+)?%'
done
# then per figure: oldest commit adding the string (git log -S over BOTH files
# jointly, so an archive sweep does not break attribution), and
# python3 scripts/loops/roadmap_scope.py --rev C   vs   --rev C~1
```

| | published | re-derived at `8beee329` |
|---|---|---|
| corpus | 11 | **10** |
| reproduce at the parent | 7 | **8** |
| reproduce at the commit itself | 4 | **0** |
| reproduce at neither | (0, implied by 7 + 4 = 11) | **2** |

**Where the 11th most likely came from**, stated as a guess: `RESUME.md`
contributes **0** under the stated form, because at that revision it spelled its
share as prose — *"7,181 lines, closed-history share 34.7% (2,493 lines across
13 closed slices)"*. Counting that form gives 11.

**The two "neither" figures** are the pair on `ROADMAP-archive.md:31573`
(`1568 / 3085 = 50.8%`, `1568 / 3197 = 49.0%`). Reading their context, they are
a later grill's arithmetic *about* 214.1's published figure, not readings of the
tree carrying them — arguably outside the corpus, and reported rather than
quietly dropped.

**What this does and does not establish.** It does not show 304's number is
wrong; it shows the number **cannot be checked**, which is what this repo's
doctrine says a load-bearing number may not be. The conclusion it supports is
untouched and is if anything strengthened: under the re-derivation *every*
reproducible figure describes the parent while printing identically to a
mid-edit reading, which is the whole argument for the header. Slice 301's own
`4,676 / 335 / 7.2%` is correctly outside both corpora — it is slash-separated
with no `=`, so the stated form does not match it.

**Not adjudicated: the `3 of 11 name a revision` half.** It depends on how wide
a window counts as "surrounding text"; ±3 lines returns 4 of 9 here. Reported as
undecidable rather than scored either way.
