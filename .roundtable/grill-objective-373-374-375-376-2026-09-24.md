## 1. Two shipped defects (filed P0)

- **A real right-click does not open the context menu** (patterns lane,
  high, Evidence). On `/components/data-table/`, a right press opens the menu on
  `contextmenu` and the button's own `pointerup` light-dismisses it:
  `toggle:open` then `toggle:closed`, final `open:false`, at 1440 and 390 —
  reproduced by three drivers (puppeteer, Playwright MCP, raw CDP). A synthetic
  `contextmenu` opens it, which is why it passed: `check-claims` has **0**
  context-menu cases and the one vitest case dispatches a synthetic event. The
  docs page tells readers to "right-click Vendor or Amount above." Measured only
  in headless Chromium on macOS, where `contextmenu` fires on mousedown;
  Windows orders it after mouseup.
- **The launcher's filter desyncs after Escape** (373+374 lane, medium,
  Evidence). Type "inv", press Escape, reopen: an EMPTY field over a grid still
  filtered to 2 of 9, status "2 applications match inv". The page binds its
  filter to `input`; Chromium's Escape-clear fires `search`. The gate's Escape
  case asserts only that the dialog closed. It is page recipe, not framework
  source — but it is the recipe readers copy.

## 3. Pointer realism — measured, with its base rate

16 of 26 behaviours register a direct pointer listener; a runtime recorder
injected into a full `check:claims` run saw **trusted** pointer events reach
exactly **8** of them. Presses made *while another control holds focus* — the
class behind 375.5/375.9/375.10 — had **zero** coverage before today. All 57
pointer-driven vitest cases are synthetic. **The base rate, measured the other

all, 6 hold under real presses at both widths; context-menu is the break. So
the pattern is ~1 in 9, not "synthetic coverage hides defects everywhere" —
which is the argument for a coverage meta-gate that names each path, not for a
blanket rewrite. Two `check-claims` comments claim a "real click" over an
in-page `el.click()`.
