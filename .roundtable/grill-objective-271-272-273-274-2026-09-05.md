## The three defects

### A. 274.1's Accept enumerates four verdicts, and one of them is false in the commit that wrote it

> `--since 2026-09-01` prints *"grew SLOWER than the file, so the whole-file row
> OVERSTATES it"*; the default window and `--since` 08-28, 08-29 and **09-04**

| `--since` | dispatch | playbooks + ref | whole file | verdict |
|---|---|---|---|---|
| 2026-09-01 | +1.7% | +4.7% | +3.4% | SLOWER |
| 2026-08-28 | +18.8% | +18.4% | +18.5% | FASTER |
| 2026-08-29 | +5.7% | +4.7% | +5.1% | FASTER |
| **2026-09-04** | **+1.7%** | **+2.2%** | **+2.0%** | **SLOWER** |

**The cause is the commit itself.** 274's own `LOOPS.md` edit — the lane-4
instruction — added **130 words** to `playbooks + reference` (7,932 → 8,062) and
**0** to the dispatch region; 274's own text records exactly that, as the second

+0.6% to +2.2% while dispatch stays +1.7%, and the comparison flips. The
four-window sweep was run against `c32491a`, the pre-edit tip, and written into
the post-edit commit.

**The criterion's property half is intact and is not in question.** The verdict
line still discriminates on real data — two windows print each branch — so the

`--self-test` passes at **12 cases**, and the `## Playbooks` anchor is present in
**87 of 87** revisions of `LOOPS.md` (86 of 86 when 274 measured it; the extra
revision is 274's own commit), so the guard's stated unprovability holds too.

**What is wrong is that the Accept names values at all.** This is CLAUDE.md's

have"* — and the sharpest thing about it is that **the same slice states the rule

The 274.1 figures that ARE attributed — the region table — carry

### C. 274.2's no-cut branch grows the region the item exists to shrink

274.2 is the open item, so this one is prospective rather than historical. Its
Accept:

> each rule in Step 2 either loses a region of history to `LOOPS-archive.md`,
> **or** carries a one-line recorded reason its history is load-bearing where it
> stands.

Step 2 holds **eight** rules. Measured on Step 2's own prose — **284 non-blank
lines, mean 11.3 words per line, median 12** — eight one-line reasons written
into Step 2 come to **+96 words**. The dispatch region grew **6,000 → 6,100,
+100 words**, between 2026-09-01 and now.

**So the branch the item explicitly blesses as satisfying — "finding nothing
cuttable satisfies it" — costs 96% of everything the region has grown in the
last four days, inside the region the item exists to shrink.** The words land
above `## Playbooks`, which is precisely the test 274.1 built the `by region`
block to apply, and precisely the ground on which 274 refused the Ideas backlog
(a cut that moves the file and not the region). The criterion is the same error

It also sits awkwardly against the criterion's own last clause — *"a cut that
leaves the dispatch region unmoved does not satisfy it"* — which reads as
refusing the no-cut branch it opens with.

The fix does not need the rule to lose its reason: it needs the reason recorded

it is diffed and reviewed, and rule 4's own precedent (167.2, and the Ideas
refusal) is that what may leave the region is history a wake needs when it
**argues** about a rule, never the sentence it **executes**. A reason a rule's
history is load-bearing is an argument about the rule.

## The transferable finding

A and B are one shape, and it is already written down. ENVIRONMENT's bullet:

> A figure describing a commit is read from THAT COMMIT, never from the working
> tree or the prose beside it. … for a figure going into the message of a commit
> that does not exist yet, the index — `git show :<file> | wc -l`.

That bullet already records being broken twice (229.5, and the commit that added
it breaking it in its own subject). These are the third and fourth, in
consecutive wakes, in the two most recent slices of the arming set.

**What is new is the source both wakes actually used, which the bullet does not
name: `HEAD`.** The bullet warns off the *working tree* and the *prose beside
it*. Neither wake read the working tree — 273 read `HEAD` (the ledger as it stood
at dispatch) and 274 ran a script that reads `HEAD` by construction. When your
own commit changes the file, `HEAD` is the pre-change state and is exactly as
wrong as the tree, in the opposite direction.

**And for a figure a SCRIPT produces, "read the index" is not available** — the
script walks revisions, and the index is not one. The available discipline is the
one 274 applied to its table and not to its Accept: **name the revision the
reading describes**, or re-run after committing and correct the number. A verdict
with no revision beside it is read as current, and a later wake re-running the
command gets a different answer with nothing to adjudicate them — which is
191.1's finding, arriving again in a different file.
