## B. Slice 307 — the P0 underneath the measurement

307 re-ran the `/stress` harness and published *"select-all 3 ms / 1k and
7 ms / 5k against the 4 ms and 18 ms below: not slower"*, and shipped a
paragraph to `/components/data-table` saying so.

**The select-all it timed did nothing.**

`/stress` gets its behaviours from the reference app's shared `page()`
template. On **2026-08-23**, `1f75dab4` reformatted that template's init block:

```diff
-  initDialogs(); initDataTables(); initAlerts(); initDropdowns();
+  initDialogs();
+  initGroupedNumber(); // grouped amounts (0.4.0), dogfooded 2026-08-23 initDataTables(); initAlerts(); initDropdowns();
```

All three calls ended up **inside the `//` comment**. Not run on initial page
load since — 15 days.

### How it was found: by a control, not by reading

The probe written to reproduce 307's number counted how many row checkboxes
ended up checked, next to its timings:

```
n=1000  rows=1000 boxes=1000 checkedAfterLast=0   select-all ms: [11.1, 6.1, 6, 5.6, 6]
n=5000  rows=5000 boxes=5000 checkedAfterLast=0   select-all ms: [43.9, 41.9, 44, 45.4, 43.3]
```

Without that `checkedAfterLast` column this wake would have published a third
set of plausible milliseconds on top of the second. The instrument was correct;
the **subject** was dead — which is the ordinary direction of CLAUDE.md's "an
instrument's first output is not evidence", and the reason a timing probe needs
a column proving the work happened.

## D. The grill broke the dispatcher's own instrument, which is how it was found

Writing section A's per-section table into `ROADMAP.md` — rows beginning
`## the loops table  214 -> 266` inside a ``` fence — made `roadmap_scope.py`
report **23 open** against a raw `grep -c` of **24**, with `OPEN:` omitting
Slice 309 while simultaneously listing 309 as a *closed* sweep target.

`## ` inside a fence was being read as a real heading. Everything below such a
row is charged to "no slice" and **falls out of the OPEN set dispatcher rule 4
reads**. `308.1` had already been swallowed by it: the previous hand-off saw the
anomaly and explained it as arithmetic (*"it also counts … 308.1"*) rather than
diagnosing it.

**The reconciliation lane behaved correctly and could not have caught this.** It
accounts for strays, so a mis-attributed marker still balances; what it cannot
see is that the marker went to the wrong place. This is the reconciliation
doctrine meeting its own edge — *assert the count* catches a marker going
unseen, not a marker filed under the wrong owner.

Fixed with a fence guard; `--self-test` gains **case F**, carrying its own
discrimination (the identical fixture with the fence removed must parse
differently, or the case proves nothing). Red-proved by removing the guard:

```
SELF-TEST FAILED (F): a `## ` row inside a ``` fence was read as a heading —
open=set() boxes=[0, 0] stray=[(5, '## the loops table …', True, '1. [ ] **4.1 …')]
```

After the fix: 24 open matching raw, `OPEN` includes 309, strays 8 → 2.

**Noticed the way `LOOPS.md` says this family is always found** — a number
disagreeing with something just written down by hand.
