## This wake's own instrument, wrong on first output

CLAUDE.md's base rate landed again, on the one probe this grill wrote. The
first version of the live width probe read `clientWidth`/`clientHeight` and
counted `.bo-data-table tbody tr` across the whole document. It returned
**896 × 382 with 36 rows** and would have reported 256 finding C as not
reproducing.

Both errors are the same mistake — measuring a box other than the one the claim
is about. `clientWidth` excludes the container's own 15px scrollbar and 2px
border (913 − 17 = 896); `clientHeight` excludes the border (384 − 2 = 382);
and the page carries **three** `.bo-data-table-container` elements, so a
document-wide row count is not this container's 14. The corrected probe reports
both readings side by side, which is what made the 17 and the 2 legible instead
of just wrong.

The tell was CLAUDE.md's own: a figure that disagrees with an independent one
already in hand. `rowsFullyInside` came back **9** — matching 256 exactly — while
the width and the row count did not. A probe that is wrong about the box is
rarely wrong about everything.
