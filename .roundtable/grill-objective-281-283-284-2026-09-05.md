## Finding 1 (285.1) — a design decision built on a measurement that is off by 16

283.2 published, and `polish_requeue.py` now ships in `parse_stamp`'s docstring:

> every stamp that reproduces anywhere reproduces at the commit that **carries**
> it — 18 of 18 — and at that commit's parent, which is HEAD as `--stamp` saw
> it, **0 of 18**. A `@rev` written by `--stamp` would therefore record the one
> revision the measurement rules out, **on every row**.

**18 of 18 is right. 0 of 18 is 16 of 18.**

### The measurement

Over the 21-row ledger at `fc79ea85` (283.1's commit — the pre-migration
ledger), for each row: find the revision of `polish-state.md` that first
contains the stamp digest ("the carrier"), then test the stamp against the
surface's digest at the carrier and at the carrier's parent, under both the
current path set and the pre-276.1 narrow one.

| | rows |
|---|---|
| rows with a stamp | 21 |
| reproduce at the carrier | **18** (as published) |
| of those 18, also reproduce at the carrier's **parent** | **16** (published as 0) |
| reproduce at neither | 3 — `data-table`, `date`, `pagination` |

```python
# scratch probe; needs `sys.path.insert(0, 'scripts/loops')`
import sys, subprocess; sys.path.insert(0, 'scripts/loops')
import polish_requeue as P
def git(*a): return subprocess.run(['git', *a], capture_output=True, text=True).stdout
LEDGER = '.roundtable/polish-state.md'
pre  = git('show', 'fc79ea85:' + LEDGER)
revs = git('log', '--format=%H', '--', LEDGER).split()[::-1]      # OLDEST first
def carrier(stamp):
    for r in revs:
        if stamp in git('show', f'{r}:{LEDGER}'): return r
def narrow(s): return [p for p in P.source_paths(s) if '/js/behaviors/' not in p]
for _, surface, cells in P.rows(pre):
    stamp, _ = P.parse_stamp(cells[4])                            # cells[4] is `src`
    c = carrier(stamp); par = git('rev-parse', c + '^').strip()
    at_c = stamp in (P.digest_paths(P.source_paths(surface), tree=c),
                     P.digest_paths(narrow(surface),          tree=c))
    at_p = stamp in (P.digest_paths(P.source_paths(surface), tree=par),
                     P.digest_paths(narrow(surface),          tree=par))
    print(surface, stamp, c[:8], at_c, at_p)
```

### Why — mechanically, not statistically

16 of the 18 carrier commits **never touched the surface's own source**. A
Polish round that is a NO-OP on its surface — most of this ledger — commits
`polish-state.md` and `ROADMAP.md` and nothing else, so the source at HEAD when
`--stamp` ran is byte-identical to the source at the commit that followed.

```
git diff-tree --no-commit-id --name-only -r a940c8f3     # component/progress' carrier
# .roundtable/polish-state.md   ROADMAP.md   scripts/loops/polish_requeue.py
#   digest at a940c8f3  = 1154a4d7   <- the stamp
#   digest at a940c8f3^ = 1154a4d7   <- identical
```

Only `byline` (`d8c9b5d1`) and `icon` (`1498b4c1`) differ at the parent, and
those are exactly the two rounds that edited their own surface in the same
commit.

### Reconciliation (this is what makes it more than a probe)

An independent predicate — *did the carrier commit touch this surface's
source?* — agrees with *does the stamp reproduce at the parent?* on **18 of
18** rows. The detector also discriminates before any injection: three distinct
outcomes on real input (18 / 16 / 3).

### What the correction does and does not change

The **decision stands, its evidence does not.** The suffix stays optional on
the ground that survives measurement, which is by construction rather than base
rate: `--stamp` cannot know, when it runs, whether the round will still commit
a source change, so it cannot write a revision it can *guarantee*. A wrong
suffix is worse than an absent one — `--audit-stamps` verifies a suffixed stamp
by ONE equality at the named revision and skips the search, so a bad row reads
as confident and is unrecoverable, where a bare stamp is merely searched for.
That is a 2-of-18 rate of silent unrecoverable error, which is a fair reason to
refuse a mandatory suffix. *"Wrong on every row"* was not.

### Where it had spread — corrected in 4 live places

`ROADMAP.md` (283.2), `.roundtable/polish-state.md`, and **twice** in
`scripts/loops/polish_requeue.py` (module docstring + the `--stamp` branch
comment), plus `parse_stamp`'s docstring where the argument actually lives.
`loop-log.md` and `STATUS.md` rows are **not** backfilled —
`record_iteration.py`'s standing rule forbids it, and a log row records what a
wake believed at the time.

### My own two dead instruments, per this repo's base rate

Both caught before producing a finding:

1. **Wrong column.** `cells[-1]` is the ledger's `status` prose, not `src`
   (`| surface | dimension | score | rounds | dry | src | status |`). Returned

   defect until proven otherwise. It was.
2. **Carrier off by one.** Walking `git log -- polish-state.md` newest-first

   revision *after* the introducing one, and `NONE` for the six rows whose
   stamp the migration replaced. That version read **12 of 15** at the parent
