## A. Slice 210's BROAD base rate is wrong, and the gate it quoted names the missing case in its own header

**Claimed** (ROADMAP Slice 210): the BROAD predicate — *any literal duration or
easing at all* — has a base rate of **"3 sites / 2 declarations"**, and *"the
three literals in the tree are `600ms` (scan), `1.8s` and `linear`
(skeleton)"*.

**Measured — 5 literal occurrences across 3 declarations.** Independent postcss
walk of the whole of `packages/core/src/css`, written from the claim rather
than from 210's method (its probe was a scratchpad throwaway, deliberately not
committed):

```
components/scan/scan.css:42       animation: bo-scan-flash 600ms var(--bo-motion-easing-standard) forwards   [600ms]
components/skeleton/skeleton.css:30  animation: bo-skeleton-shimmer 1.8s linear infinite                    [1.8s, linear]
motion/motion.css:96              animation: bo-motion-spin 1s linear infinite                              [1s, linear]
```

The third declaration — `.bo-motion-spin` — is absent from 210's enumeration
and from its count. A second, line-based sweep with a deliberately looser
predicate returns the same three declarations plus two hits that are **prose
inside comments** (`tabs.css:132`, `color.css:84`), which the postcss parse
correctly excludes; the two instruments agree on the answer.

**Where it ships, stated exactly, because the first reading of this was
overstated and corrected before publishing.** `grep -rl bo-motion-spin
packages/core/dist/` returns `dist/css/index.css` and
`dist/css/components/skeleton.css` as well as `dist/css/motion.css` — but in
the first two the string is **comment text**. The declaration ships in
`dist/css/motion.css` only: `motion/motion.css` is deliberately opt-in and is
never imported by `index.css` (`richtext.css:148` says so; the entry point is
built by `build-component-css.mjs:92`). It is a shipped artefact of the
package, it is in the source tree, and it is not under `components/` — which is
the most likely reason a components-scoped probe missed it.

**`check:motion` counts it, and that is red-proved rather than reasoned.**
Removing spin's reduce override from the generated `dist/css/motion.css` —
injection asserted unique (`count == 1`) before replacing, per CLAUDE.md —
turns the gate red naming exactly this declaration, and restoring it returns
green:

```
motion check FAILED — 1 animation(s) or transition(s) ignore prefers-reduced-motion:
  css/motion.css: ".bo-motion-spin { animation: bo-motion-spin 1s linear infinite }"
  uses a literal duration and has no prefers-reduced-motion override…
restored rc = 0
```

So the gate whose pass line 210 quoted in the same paragraph — *"animation: 17
token-driven, **6 explicit override**"* — was already counting a declaration
210's enumeration says does not exist. And `check-motion.mjs`'s own header, in
the file that pass line came from, reads: *"both literal-duration animations
(**spin**, skeleton shimmer) carry their own `animation: none` override"*.
210 named scan and skeleton and dropped spin. The cross-reference is closer
still: `skeleton.css`'s own comment — in a file 210 did read — explains its
override as *"same reasoning as `.bo-motion-spin`"*.

**The conclusion is unaffected, and is better supported than 210 argued.**

- **NARROW stays 0 of the tree**, re-derived here: the scale is
  `--bo-motion-duration-fast/base/slow = 100ms / 150ms / 300ms` and
  `--bo-motion-easing-standard = cubic-bezier(0.4, 0, 0.2, 1)`, read from
  `tokens/motion.css` by the probe. Neither `1s` nor `linear` is a token value,
  so the missed declaration does not move the NARROW count and 210's refusal on
  94.11 grounds stands untouched.
- **BROAD's refusal gets stronger.** 210 argued a BROAD gate's *"entire red set
  is three documented decisions"*. The red set is 5 literals across 3
  declarations, and the third is the most explicitly documented of them:
  `motion.css:92-94` carries a comment stating why it is not token-driven (*"a
  spinner's rate isn't a one-shot transition — reduced-motion is guarded
  explicitly below"*) and `motion.css:102-106` gives it `animation: none` under
  `prefers-reduced-motion: reduce`.

**Shape: 192.1, third instance in a row.** *The defect lands in what shipped
BESIDE the number, not in the number.* 210 spent its red-proof on the NARROW
zero — correct, and re-derived as correct here — and the BROAD enumeration
beside it went out on that credibility having earned none. This is the same
shape as 209.1 (a sweep's figures measured against a state never committed) and
as 210's own paragraph about 201.4's denominator. 210 wrote that paragraph and
then did it.

**No gate is proposed.** `check:motion` already covers this subject, on the
shipped dist, adjudicating rather than forbidding — which is 210's own
conclusion. What was wrong was a count, and 192.1's answer to a wrong count is
