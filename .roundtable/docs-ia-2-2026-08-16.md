# Docs IA pass 2 — within-group ordering + patterns grouping (Slice 20 item 2)

2026-08-16. Slice 16 fixed the top level (task-based groups, demo-first
pages). The user's follow-up ask ("rearrange the contents, components,
patterns — make it easy to understand") targets what Slice 16 didn't
touch: the order WITHIN each sidebar group, the flat 12-item Patterns
list, and a route from the landing into each group.

## Compare-first evidence (fetched live this round)

- **Tailwind**: within-section order is property-cluster/curated, NOT
  alphabetical (its Layout section runs aspect-ratio → columns →
  break-after — `columns` before `break-*` breaks alphabetical; related
  properties sit together). The curated school.
- **Ant Design**: alphabetical within categories (General: Button,
  FloatButton, Icon, Typography; Data Entry: AutoComplete, Cascader,
  Checkbox…). The scannability school.
- **Carbon**: alphabetical component list (could not re-verify live this
  round — the page truncates on fetch; recorded as high-confidence
  memory, not fresh evidence).

Two legitimate schools. Alphabetical pays off for SCANNING long lists
(Ant's Data Entry has ~20 entries; Carbon's list ~40). Curated pays off
for LEARNING short lists — a 4-10 item group read top-to-bottom is a
path, not an index. Our groups are 4-10 items. **Decision: curated,
workhorse-first, families adjacent** — the Tailwind school, which is
also the user's own reference (the version-switcher attachment came
from tailwindcss.com).

## What changed (no URLs touched — ordering/grouping only)

### Within-group ordering (was: scaffold-append order — neither school)

- **Data input**: Forms, Filters, Money field, Tag input, File upload
  (was: Forms, Filters, Tag input, File upload, Money field — the
  newest component had appended last; Money is the workhorse field and
  belongs with the foundational pair).
- **Data display**: Data table, Pagination, Amount, Quantity, Date,
  Ordered list, Tree, Dashboard, Card, Byline (was: Pagination after
  Data table but Amount/Quantity/Date scattered from Tree/Ordered list;
  now: workhorse first, its companion second, the data-type family
  adjacent, structures, then dashboard family).
- **Feedback**: Badge, Alerts & toasts, Loading empty & error, Progress,
  Stepper, Timeline & audit (Loading/empty/error moved up — state
  patterns are foundational, consulted earlier than steppers).
- **Actions** and **Navigation & layout**: already workhorse-first;
  unchanged.

### Patterns: one flat list of 12 → three workflow groups

ERP work has three modes; the patterns now group by them:

- **Patterns: capture & edit** — Invoice list, Editable grid,
  Goods receipt (RF scanner), Multi-column detail form, Validation
  summary.
- **Patterns: review & approve** — Approval workflow, Record detail,
  Multi-step wizard.
- **Patterns: overview & shell** — Reporting dashboard,
  Settings & admin, App launch, Login.

### Landing → groups

The landing page gains a compact "find it by task" contents block —
one row per sidebar group with its member components, routing a
first-time visitor into the right group without opening the sidebar
tree first.
