## This wake's own first output was wrong, and it was caught by the run, not by review

The first `scan:dead-style` run reported **10 dead on 8 pages, 1,121 live
attributes, 1,453 declarations, 249 multi-declaration** — a clean-looking
disagreement with Slice 363 on every one of five numbers, which would have been
the biggest finding here. It is contamination: the scan was running in the
background when this wake moved `apps/docs/dist` aside for the `astro check`
reproduction, so it walked a tree that was being emptied under it. Re-run with
nothing else touching `dist`, it returns **11 / 9 / 1,365 / 1,813 / 345**,
matching Slice 363 exactly.

Recorded because the failure is not the contamination, it is that the wrong
reading was *plausible*: it moved every number in the same direction by roughly
the same fraction, which reads like a genuine tree change rather than an
instrument fault. **A background measurement is a statement about the tree
across its whole run, not at the moment it was launched** — the same shape as
`ENVIRONMENT.md`'s *"a gate you ran is a statement about the tree at the moment
it ran"*, one process at a time instead of one commit.
