## A. The result, and why a 100% is not being reported as a clean bill

CLAUDE.md is explicit that **a 0%, a 100%, or an identical value across many
inputs is a defect in the instrument until proven otherwise**. A grill reporting
32/32 is exactly that shape, so the first question asked was whether this
re-derivation pipeline is capable of returning a disagreement at all.

**It is, and it did — four times, every one of them against the grill.** The
four disagreements it produced were all traced to the probe, not the claim. So
the pipeline is not stuck-green; it discriminates, and what it discriminated
was the difference between a measurement taken by running a slice's stated
command and one re-derived from the slice's prose.

That asymmetry is the finding.

| | count | wrong |
|---|---|---|
| published claims, re-run from the command beside them | 32 | **0** |
| this grill's own ad-hoc probes, written from the prose | 4 | **4** |

## B. The four defective probes, each with what made it wrong

Recorded in full because each would have been published as a defect in a
reviewed slice had its first output been trusted. All four were caught the same
way: by going back to the slice's own stated command instead of arguing with the
number.

1. **`\b284\b` matches inside `1,284,734`.** Reconciling 236.2's "what do
   still-open items NAME" check against an independent probe, the probe reported
   `249.9` naming Slice 284 where `roadmap_scope.py` reported only Slice 283.
   There is no such citation: the match is a thousands-separated byte count in
   `249.9`'s own text. **`\b` is a poor boundary for a number — a comma is a
   non-word character and therefore *is* a word boundary.** The discriminating
   needle is `(?<![\d,.])(2[89][0-9])(?![\d,])`; red-proved by discrimination —
   `1,284,734` → `[]`, `Slice 284` → `['284']`, `284.2` → `['284']`. With it the
   probe agrees with the script.

   Worth stating plainly: *"reconcile against an independent count"* is written
   in this repo for catching a dead **script**. Here the script was right and the
   reconciliation was wrong. A disagreement is a signal to investigate, never a
   verdict about which side is broken.

2. **Lane 1 probed the wrong tree.** Slice 290's lane-1 figure was re-derived
   over `packages/core/src/css` and read **0 declarations in 0 files** against a
   claim of 390 in 79 — a spectacular-looking refutation. The slice's own command
   block says `-- apps/docs/src`. Run as written it reads **390 in 79** at all
   four revisions, including today's HEAD.

3. **A synthetic "legacy 4-field row" that was not one.** 290.1's refusal rests
   on a discrimination table: a legacy row parses under `_common.parse_log_line`
   with `mode=None` and does **not** match `dispatch_status.ROW`. The probe's
   synthetic row was `- <ts> · Continue · something · landed` — and `ROW`
   **matched** it, apparently refuting the load-bearing half of the refusal.
   `ROW` is `^- (ts) · ([\w-]+) · ([\w-]+) · (.*)$`: a *single-token* item is
   consumed by the mode group. 290.1's stated form is `ts · loop · item ·
   outcome` with a real multi-word item, which `[\w-]+` cannot match. Re-run with
   all four of 290.1's own rows, the table reproduces exactly.

4. **Heights compared against widths.** 286.2's block reads `width 260` for the
   reached table against `width 310` for its three compact siblings. The probe
   measured `getBoundingClientRect().height` and reported 202 / 213 / 388 / 756 —
   a flat contradiction of a claim about widths. Re-measured as width: **260 /
   310 / 310 / 310**, exact.

**The common shape:** every failure came from reconstructing what to measure out
of the prose, and every one was fixed by running what the slice wrote down. This
is the direct continuation of **289's** finding — *"all six that do not reproduce
sit beside no command"* — arriving from the other side: the claims here all had
commands and all held, and the things without commands were the grill's own.

## D. Collision, recorded

Step 0c's mandated `git fetch origin main` **before the first commit** caught
`origin/main` two commits ahead carrying the other dispatcher's 287.5 — the same
item, taken deterministically by rule 4, as Step 0c predicts. That work was
discarded per the accept-collisions decision; the cost was one wake's item, the
stated price.

Two things worth noting against Step 0c's own text:

- **The fetch is what caught it, again** — the working half of the mechanism,
  and a process rule with nothing mechanical behind it.
- **The redundancy paid, mildly.** Slice 162's postscript argues the redundant
  cloud wake is not pure waste. Here it produced an independent second
  derivation of 287.5's answer that agrees byte-for-byte, which is section C's
  n = 2. That is not an argument for collisions; it is what this one happened to
  yield.
