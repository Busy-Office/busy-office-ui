## The question this grill was handed, and the answer

`RESUME.md` proposed the first question: **"how many other closed Accept criteria
stopped holding the day they were ticked?"** 28.1's did — its criterion was
*"`ci-wall-time` recorded every wake"*, and Slice 184 measured that the fix held
for one day.

**Measured answer: none of that shape exist. n = 1, out of 275.** The premise that
184 fixed one instance of a general rot is **false**, and finding it false is the
satisfying outcome.

### A. Exactly one Accept criterion in the corpus binds future behaviour

```
# 275 Accept criteria parsed from ROADMAP.md + ROADMAP-archive.md.
# Marker: /\*{0,2}Accept\*{0,2}\s*:/i  (covers `Accept:`, `*Accept*:`,
#   `**Accept:**`, `**Accept**:` — all four forms occur)
# Criterion bounded at the first blank line OR the next `N. [x]` item marker.
# Needle set: 21 recurring-obligation phrases.
```

| needle set | criteria matched |
|---|---|
| 11 phrases (`every wake`, `each wake`, `every run`, `every commit`, …) | 5 |
| widened to 21 (adds `from now on`, `going forward`, `thereafter`, `continues to`, `every future`, `future wakes`, `recurring`, `each subsequent`, …) | **4** |

Widening the needle set by ten phrases added **zero** new hits, which is the
robustness check — the phrase space is saturated, not under-sampled. The count
*fell* by one only because `each run` was dropped as a defect (below).

**Hand-read verdicts on all four** — the classification is semantic, so it is
mine, not the instrument's:

| hit | verdict |
|---|---|
| `ROADMAP.md:356` — 184.1's own Accept | **Not an obligation.** "every wake" appears where it quotes 28.1 as the source of its threshold. What 184.1 requires is that a line *prints* — mechanical, checked by running the script. |
| `ROADMAP.md:2588` — 162.1, OPEN owner call | **Incidental.** "every time" is inside the collision argument, not a criterion. |
| `ROADMAP-archive.md:320` — **28.1** | **The one genuine recurring obligation.** *"`ci-wall-time` recorded every wake"*. Decayed within a day. |
| `ROADMAP-archive.md:20124` — 169.3 | **A description, not an obligation** — "a file that is **not** rewritten every wake" describes `ENVIRONMENT.md`'s nature. Holds today; the file exists. |

**1 of 275 = 0.4%.**

**The instrument was wrong on its first run, twice, and both were caught before
the number was quoted** — the base rate this repo records for new detectors held
again:

1. **Block over-capture.** Bounding the criterion at "the next item or heading"
   swallowed hundreds of lines of following prose and reported **19** hits;
   `on every` was landing in narrative like *"prints on every docs build"*, not
   in any criterion. Tightening to the criterion paragraph gave 11, then 5.
2. **A substring false positive.** `each run` matched inside **`each rung`**
   (`ROADMAP-archive.md:12099`, the richtext-ladder item). Verified directly —
   `grep -o 'each run.'` returns `each rung` — and the needle was dropped.

### Why the rot is *not* general, measured from the other side

Of the same 275 criteria, **117 (43%) name a gate, script or test** (`check:`,
`npm run`, a `.mjs`/`.py` path). Those re-check themselves on every build by
construction. The rest are one-shot assertions about an artefact that exists at
tick time — a page renders, a count agrees, a file moved.

So the criterion system is overwhelmingly **artefact-based**, and CLAUDE.md's own
rule pushes it there: *"An Accept criterion names the PROPERTY to verify, never
the value it will have"* is satisfiable by measuring **once**. 28.1 is the single
criterion that tried to bind what the loop would keep doing, and it is the single
one that failed.

**Conclusion (Evidence — two independent measurements, the phrase sweep and the
mechanical-criterion count, agreeing):** 184.1 did not patch one leak in a leaky
system. It supplied a mechanism for the one thing the Accept-criterion form
**structurally cannot express**. Counter-evidence, stated: n = 1 is a weak base
for any claim about a class, and the phrase sweep can only find obligations that
were *written down as* obligations — a criterion that silently assumes ongoing
behaviour without saying so is invisible to it. That limit is real and is why the
finding is scoped to "as written", not "as intended".

### Base rates — two predicates, one weak and one sharp

**Weak (a proxy, reported as one):** wakes that changed `ROADMAP.md`'s
open-checkbox set without touching `RESUME.md`.

```
# history split into 60 wakes at each `record iteration` commit
wakes where the open-checkbox SET changed:            42
  ... of those, wakes that never touched RESUME.md:   22   (52%)
```

52% is not by itself a defect count — a wake that closes an item `RESUME.md`
never names leaves nothing stale. It is reported because it bounds the exposure,
not because it is the finding.

**Sharp (exact, no semantics):** at each wake-end commit, does `RESUME.md` name
in backticks a slice id that `ROADMAP.md` records as `[x]` closed?

```
evaluated at 58 wake-ends (60 minus 2 predating both files)
wake-ends where RESUME named a CLOSED item:  2  (3%)
   2026-08-28 4be166be  ['177.1']
   2026-08-29 751959eb  ['175.4']      <- HEAD
```

**3% — not 0, not 100.** The predicate discriminates (94.11), and it catches the
live instance.

**Noise, measured before proposing anything:** across all 80 revisions of
`RESUME.md` there are **83** backticked slice ids in total — about **one per
revision**, and on today's file all six are exactly the members of the
blocked-set claim. A reconciliation here is quiet, not a wall of false hits.

**My own parser under-reported first, and was reconciled rather than trusted.**
Matching `^\s*\d+\. \[ \] \*\*([\d.]+)` found **4** open items where a raw
`grep -c` of `N. [ ]` gives **5**: `15.12` is written `12. [ ] **AT runtime
evidence**`, with no numeric id in the bold. That is CLAUDE.md's `STATUS.md`
failure (7 of 9) reproduced exactly, in the instrument written to measure a
mirror. Fixed by carrying unnumbered items as `(unnumbered)…` and asserting

## C. What 180, 183 and 184 have in common

All three are failures of a **self-description**: a piece of metadata the loop
keeps about its own machinery. In each case the description was checked against
the wrong thing, or against nothing.

| slice | the self-description | what checked it |
|---|---|---|
| **180** | `check-slice-refs`' `@exact` tag — a claim about what kind of detector it is | `check:selftests`, which read the **tag text**, not the code. The other arm was a bare word regex over free prose, and real prose fooled it. The same gate's header also claimed "148 slice numbers are cited" while its own run line read 362. |
| **184** | dispatcher rule 5's verdict — a claim that a metric had not regressed | **Nothing.** `dispatch_status.py` exists *because* rules starve silently and had never read `loop-metrics.jsonl` at all. 10 wake-dates of drift; the stale reading was published into the plan. |
| **183** | `RESUME.md`'s "these five need a local wake with a browser" | **Nothing, for eight wakes.** |

**183 is the control, and it is what keeps this honest.** When that
self-description was finally checked, **5 of 5 items were clean — no defect
found**. A stale self-description is not automatically a defect; here it cost
eight wakes of carrying and produced nothing. So the finding is *"self-descriptions
are unverified"*, **not** *"self-descriptions are wrong"* — the second does not
follow, and 183 is the counter-evidence against asserting it.

Finding B extends the row set: `RESUME.md`'s blocked-set claim is a fourth
self-description, checked by nothing, and wrong at HEAD.

**Verdict (Hypothesis, not Evidence — n = 4 slices, one corpus, no independent
external source):** the framework's *product* surfaces are densely gated (43
gates, 15 self-tested), and the *loop's own* surfaces are gated far more thinly.
184.1 built the first instrument that reads a dispatcher rule's input. It is a
first, not a last.

**Refused here, deliberately:** proposing a general "gate every self-description"
programme. 176.2 measured rule 6's predicate as true of 19 of 19 surfaces, and
94.11 measured a comment-presence predicate true of 155 of 155 literals — this
repo's recorded failure mode is exactly the plausible-sounding blanket gate that
distinguishes nothing. One reconciliation, with a 3% base rate measured first, is
the whole proposal.
