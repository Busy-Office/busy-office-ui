# Grill: "simplicity & maintainability & easy for AI to manage —
# but also presentation to human to monitor" (owner, 2026-08-22)

The idea under grill, restated so it can fail: **this project is operated
by an AI and overseen by a human; every artifact should therefore be
simple, maintainable, AI-manageable, and human-monitorable — and those
four should be the standing rubric.**

## Verdict up front

**Adopt the quartet as the standing rubric — it is already this repo's
operating system, built piecemeal — and the grill's real finding is that
the WORST violator of all four criteria today is ROADMAP.md itself.**
Two improvements queued; one owner item re-surfaced.

## Finding 1 — the idea is already implemented, piecemeal

Each criterion maps to machinery that already exists and already has
teeth. The quartet doesn't add a new value system; it NAMES the one in
force:

| Criterion | Existing machinery |
|---|---|
| Simplicity | Objective §1 (accept/refuse/rethink tests, 60+ recorded refusals) |
| Maintainability | Standardize loop + chokepoint gates (dist-walkers, wrong-choice-rule, paths.mjs) + generated-never-hand-written docs |
| AI-manageable | CLAUDE.md recipes, red-prove discipline, 32 self-classified gates, llms.txt, RESUME.md handover, "don't assume prior-turn state" |
| Human-monitorable | loop-log (human line per iteration), grill reports in .roundtable/, loops.db for queries, the storage doctrine's whole point |

Consequence: the quartet should not become a NEW scoring apparatus
(101.3's stop rule stands) — it becomes the named lens for 109.3's
quality bar and future grills. A rubric that renames existing tests
costs nothing; a fifth scoring system would fail its own simplicity test.

## Finding 2 — the criteria genuinely conflict, and the repo has measured it

Worth stating so the rubric is used honestly:

- **AI-manageable vs simple**: an AI manages best with exhaustive written
  state; simplicity wants less prose. Measured live: the 101 grill found
  **78% of one session's shipped-source additions were commentary** —
  internal value, zero consumer bytes. The rubric must ask "which
  criterion does this serve?" not "more of all four".
- **Human-monitorable vs AI-throughput**: every load-bearing-number rule
  in CLAUDE.md exists because an unchecked measurement once reached the
  human ("1 of 18" vs the true 16 of 18). Monitoring is only as good as
  the honesty discipline feeding it — presentation without red-proved
  numbers is worse than no presentation.

## Finding 3 — the worst violator of all four criteria is ROADMAP.md

Measured this wake: **11,657 lines. 92 slices, 78 fully closed. 6,961
lines (60%) are pure closed history.**

- **AI-manageable**: fails — every wake reads this file "fresh" per the
  wake prompt; 60% of what it reads cannot change any decision.
- **Human-monitorable**: fails — the owner cannot review an 11.6k-line
  file; monitoring happens through chat summaries instead, which is
  exactly the channel the number-honesty rules distrust.
- **Simplicity/maintainability**: line-number citations into it have
  already drifted ~3000 lines twice (RESUME.md, caught by the sweep).

Precedent for the fix already exists in-repo: the DESIGN-GRAPH rule
("keep under 200 lines — compress older deltas to a pointer") and the
storage doctrine (markdown stays source of truth, in git, diffable).
**Queued as 110.4**: closed slices move to `ROADMAP-archive.md` —
same format, same git history, one pointer line each in ROADMAP.md —
mechanical, red-provable (every archived slice reachable, zero open
items archived, item-number references still resolve).

## Finding 4 — "presentation to human to monitor" names a real gap

The owner's parenthetical is the demand signal the framework's own rules
require before building a surface. Today the human monitors through:
chat summaries (distrusted by construction), `git log`, tail of
loop-log, and raw ROADMAP. There is no "now" view — open items by slice,
counters, owner-blocked list, last N iterations — even though every input
for one already exists structured (loops.db, dispatch_status, the
checkbox scan this grill ran).

**Queued as 110.5, grill-first shape**: a generated `STATUS.md` —
derived, rebuildable (mirrors doctrine), regenerated by
`record_iteration.py` so it can never drift from the log, and small
enough to read in one screen. Explicitly NOT a web dashboard (new
surface, new maintenance — fails criteria 1 and 2); a markdown file the
owner can read in ten seconds. If in practice the owner keeps reading
chat summaries instead, 110.5 gets deleted as ceremony — that test is in
its Accept.

## Re-surfaced, not new: the standing wake prompt (102.4, owner call)

Still the clearest AI-manageability defect on the books: the prompt
driving every wake names Slice 94 as active and a seven-dimension rubric
— both false for weeks. A wake spends its first tokens reconciling
instructions it cannot fix. The owner updating that prompt (or blessing
the drift) remains a one-minute action only they can take.
