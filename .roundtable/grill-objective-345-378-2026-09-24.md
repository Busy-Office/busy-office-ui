## 1. Slice 345 / item 345.1

- **F1 (medium, Evidence): a block spinner changes layout.** 345.1's own
  Accept asked what an inline-block default "would break for a consumer who
  wants a block or flex spinner", and the close answered only for consumers
  who set `display` themselves. Measured against HEAD and `b29e4179^`, with and
  without the reset:
  - A sized `<div class="bo-motion-spin">` ring with `margin-inline: auto`
    sits at offsetLeft **184 → 0**.
  - `<div class="bo-stack bo-motion-spin">` computes `inline-block`, not
    `flex`, because the utility layer outranks the component layer.

  **Kept, with the break documented.** No shipped page, component or example
  uses either shape: `git grep bo-motion-spin` over `packages/`,
  `apps/docs/src` and `examples/` finds only `motion.astro`'s two `<span>`s and
  a `.bo-icon`, which is inline-block already. The change is also unreleased.
  The CHANGELOG entry now has a **Migration** note naming both shapes and the
  fix. A consumer's own `display: block` re-centres the ring: offsetLeft 189 in
  a 400px host with an 8px body margin, which is centred.
- **F2 (low, Evidence): the rule un-hid a hidden spinner without the reset.**
  With `motion.css` imported alone, `<span class="bo-motion-spin" hidden>`
  computed `inline-block`. The rule is now `.bo-motion-spin:not([hidden])`, and
  the span computes `none` with and without the reset (probe
  `spin379.mjs`). The verifier's counter-evidence: `.bo-motion-collapse`
  (`display: grid`) already had this property before 345.1, so the module
  already assumed the reset. That is recorded here, not fixed. Collapse panels
  are toggled by `data-state`, not `hidden`.
- **F3 (low, Evidence): Slice 345's `inline-size: 100%` refusal rests on a
  false reason.** The three are dead in plain block flow too (288 → 288,
  384 → 384, 256 → 256 px), so "dead only against `section.demo`'s flex
  stretch" is false. `login.astro:31` is not the identical idiom: it adds
  `margin-inline: auto`, and that makes it live, but only inside a flex or grid
  parent. At `161ede68` the markup and CSS were byte-identical, so the reason
  was false when written. The verdict stands on the corrected ground, which is
  now recorded in place.
- **F4 (low, Evidence): "32-36px wide" is not the box.** The demo span is
  **16×36px** at both widths and in both themes, in `dist` and on `:8081`. Its
  rotating rect spans about 16-40px. The 345.1 wake's own script read the
  rotating rect once, after its sampling loop. Corrected in place.
- **F5 (info, Evidence, upgraded from Hypothesis): the drift instrument could
  not fail.** The 345.1 wake measured "0px centre drift" as the spread of
  bounding-rect centres. Rotating about `transform-origin: center` never moves
  that centre, so it reads 0 on the old orbiting demo as well. On that demo the
  glyph's text Range drifts 911.7px at 1440 and 325px at 390. The property
  holds: glyph-Range drift is 0.00 on the current demo at 1440/390 in light
  and dark. The claim now names the Range instrument.
- **F6 (info, Evidence): "written as the recipe is" overclaims.** The demo
  carries an inline `font-size: var(--bo-font-size-xl)` and a `<p>` that the
  copyable recipe does not. Reworded in place. Rotation and display are
  unaffected.
- **F7 (info, Hypothesis): AppTile's comment is stale.** It says a badge chip
  is 37px tall against the icon's 32px. It measures 30px on this machine's
  font stack, so BOX's `block-size` pads the box up (30 → 32) rather than
  capping it down. The comment now says both. The refusal stands: `block-size`
  is live on the AP and AR tiles.
- **F8 (info, Evidence): three line citations in Slice 345 have moved.**
  342.1's own comments shifted them: AppTile `MARK` 43 → 51, events `<ul>`
  44 → 48, tokens swatch 153 → 158. **Not rewritten.** The citations are to
  the files as they stood at `161ede68`, which is where 345 describes them.
